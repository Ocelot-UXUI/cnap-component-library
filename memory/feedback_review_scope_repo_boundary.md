---
name: 审查/补充规范时的目标仓库边界
description: 用户说"审查/补充前端规范"时，对象是当前工作的仓库自身，不要跨仓库改另一个项目
type: feedback
---

用户让"审查 cnap2.0 / 补充前端规范"时，指的是审查**当前正在工作的那个仓库自身**（frontend-v2 = CNAP2.0），把该仓库代码里已有但规范文档未覆盖的内容补进**该仓库自己的**规范文档。

**Why:** 有一次用户说"cnap2.0 新增了组件定制 token，看看有哪些可以补充到当前的前端规范"，我误解成"把 cnap2.0 的做法搬进 tiki(team-agents) 的规范"，跑去改了 team-agents/frontend/AGENTS.md，被用户当即纠正并拒绝改动（"你怎么开始改tiki的代码了""我让你审查的是cnap2.0啊"）。

**How to apply:** 当请求是"审查某项目 + 补充规范"时，默认目标仓库 = 被点名的那个项目本身，且改动落在它自己的规范文档里。跨仓库借鉴/搬运必须先明确确认。方向不确定时先问一句，不要直接动手改文件。
