# CNAP Application Layout Guidelines

## Purpose

定义 CNAP 2.0 应用外壳的视觉布局规范。本文基于 Figma 节点“布局规则”整理，仅描述布局与交互规范，不直接要求编码实现。

## App Shell Structure

CNAP 页面外壳由以下区域组成：

- 顶部导航栏：固定在页面顶部，高度 56px，横向贯穿整个应用窗口。
- 一级侧边导航：固定在左侧，宽度 60px，位于顶部导航下方。
- 二级侧边导航：仅在需要二级导航的工作区显示，位于一级侧边导航右侧，展开宽度为 200px，收起宽度为 60px。
- 页面内容区：承载业务页面主体内容，位于顶部导航、一级侧边导航和可选二级侧边导航之后。

## Global Top Navigation

顶部导航在线上环境和沙盒环境中由云上百度统一 Header 承载，本地开发使用自定义 Header 作为占位：

- 高度固定为 56px。
- 线上环境和沙盒环境不自行实现完整 Header，只配置云上百度 Header 允许自定义的内容。
- 当前明确可自定义的内容包括产品名称、面包屑等上下文展示信息。
- 云上百度 Header 中搜索、辅助功能、用户头像和更多操作等区域的可定制范围暂不确定，需要结合接入文档或实际集成能力进一步分析。
- 本地开发占位 Header 仅用于模拟产品名称、面包屑和必要上下文展示，不应作为线上 Header 视觉与能力的唯一真源。
- 面包屑从 CNAP 入口开始，后续展示账号名称和当前页面标题；账号名称可带切换，用于表达当前资源账号可切换。

## Primary Sidebar

一级侧边导航表达顶层工作区：

- 宽度固定为 60px。
- 起始位置位于顶部导航下方，即 top offset 为 56px。
- 背景使用深色面板。
- 一级导航分为业务图标区和底部辅助图标区。
- 底部辅助图标区固定展示，例如通知、设置、同步、帮助等，不参与业务图标收敛。
- 业务图标区包含常态化展示的业务图标和排列在最后的“更多”图标。
- 主导航项以纵向图标加文字呈现，每项基础尺寸约 52px x 52px。
- 导航项之间垂直间距约 8px。
- 激活态使用浅绿色背景，文本和图标切换为深色。
- 非激活态文本为白色，图标保持轻量视觉。

## Primary Sidebar States

一级导航需要覆盖常规、选中、更多和从更多中选择隐藏工作区的状态：

- 常规视口下，业务图标区承载主页、事务、应用、环境、变更、资源、账户等顶层工作区。
- 当前激活的业务图标应始终在业务图标区直接展示，即使该图标原本来自“更多”弹层。
- active 态只属于具有业务含义的入口；“更多”只是 overflow trigger，不是业务入口，因此没有 active 态。
- “更多”入口可以有 hover、focus 或 popover open 状态，用于表达当前控件交互状态，但不能表达当前业务位置。
- 从“更多”中选中某个业务图标时，该图标替换“更多”图标前的最后一个业务图标；被替换的业务图标自动进入“更多”弹层。
- 当浏览器窗口高度缩小时，业务图标按排列顺序从后往前进入“更多”弹层，但必须跳过当前激活的业务图标。
- 在任何高度下，业务图标区至少保留一个业务图标和一个“更多”图标。
- 小屏高度不足时，一级导航仍保持 60px 宽。
- 底部辅助图标不参与主导航收敛；hover 时可展示轻量 tooltip，例如“通知”。

## Primary Sidebar Overflow

一级侧边导航存在空间不足时的收敛规则：

- 业务图标收敛判断不需要累计每个业务图标的配置高度。
- 实现时应整体获取业务图标容器、底部辅助入口容器和整个一级导航容器的高度或布局边界。
- 是否触发业务图标收敛的判断条件是：根据上述容器测量结果计算出的业务图标容器与底部辅助入口容器之间的实际距离小于 52px。
- “更多”是业务图标区中的固定入口，始终排列在当前可见业务图标之后。
- 当触发业务图标收敛时，从常态业务图标排列顺序的末尾开始倒序隐藏，但跳过当前激活的业务图标。
- 被隐藏的业务图标进入“更多”弹层，弹层中的顺序应保持信息架构定义的业务顺序。
- 如果当前激活业务图标来自“更多”，它应替换“更多”前的最后一个可见业务图标，被替换项进入“更多”。
- 业务入口图标的替换结果应在整个浏览器会话内保持，可通过 LocalStorage 缓存。
- 任何情况下都不能让业务图标与底部辅助图标重叠，也不能隐藏“更多”图标。
- 更多弹层打开时，更多入口可使用浅绿色透明背景表达当前交互焦点，但该状态不是 active 态。

## Primary Sidebar Overflow Principle

一级导航溢出交互的中心思想是：一级导航的 active 态永远表达当前业务位置，而不是表达当前交互控件。

- “更多”只是容量管理入口和溢出容器触发器，不应建模为可选中的业务导航节点。
- 用户真正进入的是“账户”“资源”“应用”等业务模块，active node 必须始终指向这些业务节点。
- 当隐藏在“更多”弹层中的业务入口成为当前业务位置时，它必须提升到一级导航可见区域，让用户不打开弹层也能看见当前位置。
- 替换“更多”上方最后一个可见业务图标，是为了在不增加一级导航高度、不挤压底部辅助图标的前提下暴露当前业务位置。
- 该设计的最终目标是在有限高度中优先展示当前业务上下文，同时保持导航容量稳定、布局可预测、不会因隐藏入口被激活而产生额外重排。

## More Popover

“更多”弹层承载被收敛的一级工作区：

- 弹层从一级导航“更多”入口右侧展开，宽度约 196px，背景为深色面板，圆角约 12px。
- 弹层内边距约为上下 12px、左右 8px，功能项横向排列，单项尺寸约 52px x 52px，项间距约 8px。
- 顶部可显示“更多功能”分组标题，字号约 10px，行高约 18px，颜色使用弱化中性色。
- 弹层内选中项使用浅绿色背景和深色文字；hover 项可使用浅绿色透明背景和白色文字。
- 从弹层选择工作区后，弹层应关闭，被选择的业务入口进入一级导航可见区域并呈现 active 态，同时按该工作区配置决定是否显示二级导航。

## Secondary Sidebar

二级侧边导航表达当前工作区内的页面集合：

- 仅在当前工作区存在二级导航时显示。
- 展开态宽度为 200px，起始位置位于一级导航右侧和顶部导航下方。
- 展开态背景使用白色，并通过轻量阴影与内容区分层。
- 展开态顶部显示当前工作区名称，字号约 16px，行高约 24px，顶部间距约 24px。
- 展开态二级导航项宽度约 176px，高度约 38px，圆角约 8px，项间距约 4px。
- 激活态使用浅灰背景，文字颜色加深且字重提高；非激活态使用中性色文本。
- 可在底部保留折叠或收起入口。
- 二级导航折叠状态不记录用户偏好，不需要持久化到长期存储。
- 二级导航折叠状态是当前会话内的独立布局状态：用户打开后保持展开，用户折叠后保持收起。
- 切换一级业务入口后，应保留上一个工作区留下的二级导航折叠状态，不因工作区变化自动重置。

## Secondary Sidebar Collapsed Rail

二级导航收起态以图标 rail 表达当前工作区内页面集合：

- 收起态宽度为 60px，位于一级导航右侧，背景为白色并保留轻量阴影。
- 收起态只展示二级页面图标，不展示文字，适合内容区需要更多横向空间的页面。
- 图标项 hover 或 active 时可展示 tooltip，tooltip 文案应为二级页面名称，例如“设置”。
- 有收起态二级导航时，内容区左侧起点按 60px 一级导航、60px 二级 rail 和 32px 内容间距计算。
- 展开态二级导航时，内容区左侧起点按 60px 一级导航、200px 二级导航和 32px 内容间距计算。

## Page-Level Category Tabs

页面存在下一级分类时，分类应位于页面标题行，而不是进入全局导航层级：

- 页面级分类 tabs 应实现为子路由，这是产品实现原则。
- 每个分类 tab 都应对应一个可直接访问的完整 URL，用户刷新或复制 URL 后应能直接进入目标分类页面。
- 分类 tab 不应只作为页面内临时 state 或 query 参数切换，否则会破坏深链访问和 Agent 导航定位能力。
- 标题行左侧展示页面标题，标题右侧可通过 1px 宽、约 20px 高的分隔线连接分类 tabs。
- 标题与分隔线、分隔线与分类 tabs 之间保持约 24px 间距。
- 分类 tabs 横向排列，项间距约 32px。
- 激活分类使用深色文字、较高字重和 2px 高下划线；下划线圆角约 4px。
- 非激活分类使用弱化中性色文字。
- 标题行右侧保留页面级动作区域，动作不得挤压分类 tabs 的最小可读空间。

## Content Area Spacing

页面内容区的边距遵循以下规则：

- 无论是否存在二级导航、二级导航处于展开还是收起状态，右侧主要内容区域都保持左右两侧各 32px 的距离。
- 无二级导航时，内容区左侧与一级侧边导航之间保持 32px 间距。
- 二级导航收起时，内容区左侧与 60px 二级 rail 之间保持 32px 间距。
- 二级导航展开时，内容区左侧与 200px 二级导航之间保持 32px 间距。
- 内容区右侧与窗口边缘保持 32px 间距。
- 顶部导航下方到页面标题之间保持约 24px 间距。
- 页面标题到主体内容区域之间保持约 16px 间距。
- 页面底部与窗口底部保持约 24px 间距。
- 主体内容容器可使用白色背景、12px 圆角、浅色边框和轻量阴影，以区分应用背景。

## Content Container

业务内容容器用于承载页面主体：

- 背景为白色。
- 外层应用背景为浅灰色。
- 容器圆角约 12px。
- 边框使用浅色中性色。
- 阴影非常轻，主要用于层级提示，不应产生强卡片感。
- 容器应随视口宽度自适应，避免固定 1440px 宽度写死到实现中。

## Layout Variants

Figma 展示了以下典型布局：

- 无二级侧边导航的主页面布局：顶部导航 + 一级侧边导航 + 页面内容区。
- 有二级侧边导航展开态的工作区页面：顶部导航 + 一级侧边导航 + 200px 二级导航 + 页面内容区。
- 有二级侧边导航收起态的工作区页面：顶部导航 + 一级侧边导航 + 60px 二级图标 rail + 页面内容区。
- 带页面下一级分类的页面：全局导航层级不增加，分类 tabs 放在页面标题行。
- 小屏高度不足的页面：一级导航自动收敛部分工作区到“更多”，底部辅助入口保持稳定。
- 从“更多”选择隐藏工作区的页面：选中工作区在当前浏览器会话内显现在一级导航中，并展示该工作区对应二级导航。

实现时应将一级导航、二级导航、更多弹层和页面标题区视为 Layout 层能力，而不是业务页面内部组件。

## Implementation Guidance

- 布局组件应由路由外壳或 Layout 层负责，业务组件不应自行决定一级/二级导航和全局边距。
- 布局职责可以嵌套存在：外层 Layout 定位全局区域后，内部容器如果继续负责其子内容的位置、尺寸、排列或可用空间，也应视为 Layout。
- 任何承担布局职责的组件都应以 `Layout` 结尾，不使用 `Shell` 命名；业务状态、持久化和交互规则应放在 Container、hook 或纯函数中。
- 导航配置模型只需要区分一级业务入口和二级业务入口，避免为当前固定 UI 控件引入过度抽象。
- 页面级分类 tabs 虽然实现为子路由，但不属于一级或二级导航配置，不应与一级/二级导航代码混在一起。
- 底部辅助入口和“更多”入口不随业务变化，可在一级导航 UI 组件内固定实现；“更多”仍作为 overflow trigger 参与业务入口展示计算。
- 不应照搬 Figma 导出的绝对定位结构；实现应使用 Flex 或 Grid 表达应用外壳。
- Figma 中的红色和橙色标注仅表示尺寸说明，不属于产品 UI 元素。
- Figma 中的页面内容占位不是实际业务空状态，不应作为业务组件设计依据。
- 视觉数值可作为基线 token，但应结合当前项目已有 `AppLayout`、`PageLayout` 和导航系统实现逐步对齐。

## Resolved Decisions

- 本地实现中的顶部上下文选择器需要与 Figma Header 占位视觉对齐；线上和沙盒环境仍以云上百度统一 Header 的实际接入能力为准。
- 二级侧边导航折叠入口进入当前首个实现切片。
