# Navigation System Design

## Purpose

定义 CNAP 2.0 导航系统的稳定应用层设计。本文承接 `docs/requirements/cnap2-sidebar-navigation-mvp.md`，描述用户可感知的导航行为和业务语义。

## Product Model

CNAP 2.0 导航系统由三类用户可见导航组成：

- 侧边一级工作区导航：表达用户当前处于哪个工作场景。
- 当前工作区二级导航：表达当前工作区内可进入的主要业务页面。
- 顶部上下文导航：表达当前账号、应用、环境，并驱动页面数据范围。

侧边导航负责切换工作场景，顶部上下文导航负责切换业务上下文。两者职责分离，但共享同一份导航上下文。

## Workspace Navigation

一级工作区至少包含：

- 主页：个人 Dashboard。
- 应用：应用列表、应用详情及应用级能力入口。
- 环境：账号下环境管理入口。
- 变更：部署、流水线、变更历史等变更流程入口。
- 资源：集群等基础资源管理入口。
- 账户：账号设置、权限、标签等账号级入口。
- 辅助入口：AI 助手、更新日志、个人设置等系统辅助入口。

“事务”工作区暂不进入 MVP，但导航结构应允许后续加入待审批、审批记录和红点提示。

## Secondary Navigation

当前工作区激活后，可展示该工作区的二级导航。MVP 范围：

- 应用：应用列表、工作负载、运行配置、应用设置。
- 环境：环境列表、环境配置。
- 变更：部署、流水线、变更历史。
- 资源：集群。
- 账户：账户列表、基本信息、角色和权限、标签。

二级导航可以分组。宽版本可显示分组标题，窄版本可用分隔线。

## Context Navigation

顶部账号、应用、环境选择器需要提供最小可用实现，用于真实驱动导航上下文。MVP 不要求最终视觉重构。

账号、应用、环境存在硬性层级关系：

- 账号是应用的上级。
- 应用是环境相关运行态的上级。
- 下层上下文不能脱离上层上下文独立存在。

行为规则：

- 切换账号后，必须重新校验当前应用和环境；若不属于新账号，应清空或回退到可选择入口。
- 切换应用后，必须重新校验当前环境；若该应用不能在当前环境下成立，应清空或回退到可选择入口。
- 选择环境时，必须基于当前账号和应用的可用范围。
- 需要应用的页面必然依赖账号；需要环境的页面通常依赖账号和应用。

该层级关系应由显式状态机管理，而不是散落在选择器、导航工具和页面组件中。状态机拥有账号、应用、环境的当前值、候选项、合法性校验和重置规则。用户操作和 Agent 能力调用都应通过同一套状态转移进入该上下文模型。

工作区是一级路由，工作区下对应的二级导航是二级路由。上下文需求配置应放在二级路由层级，不按工作区整体固定决定。

二级路由以下的三级、四级等子路由必须继承所属二级路由的上下文配置，并且不允许覆盖。具体二级路由需要哪些上下文不在本文中枚举；代码设计需要支持不同二级路由拥有不同上下文需求。

## Workspace Switch Behavior

切换工作区时，系统不主动清空顶部账号、应用、环境上下文，但目标页面只消费所属二级路由声明需要的上下文。

MVP 只要求向目标工作区、子应用和具体业务页面提供上次访问时相同的上下文信息。具体业务页面按所属二级路由上下文需求决定使用账号、应用、环境中的哪些信息；完整页面内容、筛选条件、滚动位置和组件内部状态的恢复不属于 MVP。

每个工作区应有默认页。若无法恢复或使用该工作区最近上下文，应根据目标页面的上下文需求进入默认页或可选择入口。

## Context Preservation And Reachability

顶部上下文切换后的页面保活，是根据当前路由所属二级路由的上下文需求判断用户原本页面意图是否仍可成立。

- 若成立：保持当前页面意图，只替换上下文并更新页面数据。
- 若不成立：保留当前路由意图并标记不可达，不自动跳转到其他页面。

导航失败或上下文缺失时不得用其他路由替换用户目标。工作区默认页只能用于显式进入工作区时的初始目标，不能作为失败后的隐式目标。

## Agent Navigation Semantics

本 MVP 的 Agent 化导航只关注结构化导航能力，不包含 `data-ai-*` DOM 定位和 DOM 操作兜底机制。

Agent 应能从导航元数据理解：

- 可用导航目标。
- 所属工作区和二级分组。
- route key 和必要参数。
- 当前目标所属二级路由的账号、应用、环境上下文需求。
- 当前上下文事实与目标上下文需求之间的差异。

Agent 执行导航时应使用 route key 和参数，不硬编码 URL。

导航能力层只向 Agent 返回可验证的业务事实，不返回面向用户的话术、固定追问文案或下一步动作建议。缺少参数或上下文时，能力层应返回缺失项、当前上下文、目标需求、失败阶段和相关语法信息，由 Agent 自主理解并决定如何继续与用户交互。

## Non Goals

- 不考虑移动端导航和抽屉菜单。
- 不实现 Ctrl+K / Cmd+K 快捷搜索。
- 不实现真实状态数量接口。
- 不实现权限驱动菜单裁剪。
- 不实现完整顶部选择器视觉重构。
- 不实现完整页面历史内容恢复。
