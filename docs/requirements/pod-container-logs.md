## Goal

在 Pod Detail Drawer 的容器「日志」子 Tab 中，实时展示当前选中容器的日志。支持切换日志来源（标准输出 / 容器内文件）、自动刷新（跟随流式增量）与暂停（暂停时后台继续接收并缓存、开启后续接 append）、给最新日志打分隔标记，以及搜索与全屏查看。

## In Scope

- 日志内容区：深色控制台样式，逐行渲染日志，按日志级别着色（INFO / WARN / DEBUG / ERROR 等）
- **日志来源切换**（工具栏第一个开关）：标准输出 ↔ 容器内文件，对应接口 `source` 参数
- **文件路径输入**：来源=文件时新增 `filePath` 输入框，用户输入并点击确定后以该值作为 `filePath` 拉取日志
- **自动刷新暂停/开启**（右侧暂停按钮，默认开启）：控制是否**渲染**跟随的流式增量日志；暂停时不关闭底层请求，仅停止向视图追加并把增量缓存起来（带缓存上限），开启后把缓存增量续接 append 并继续跟随
- **标记分隔线**（小旗子图标）：在当前最新一条日志下方画一条分隔线，用于区分"刚更新"与"历史"日志（纯前端视觉）
- 日志搜索（搜索框）
- 状态/级别筛选（工具栏下拉框）
- 全屏查看
- 首次进入以固定 `tailLines` 建立流式跟随（返回"当前 tailLines 行 + 请求后续新增"）
- 切换容器 / 切换来源时重置并重新加载

## Main User Flows

### 流程 1：进入日志 Tab（默认标准输出 + 跟随）

1. 用户在 Pod Detail Drawer 选中某容器并切到「日志」子 Tab
2. 默认来源=标准输出、自动刷新=开启（follow）
3. 前端以固定 `tailLines` 建立流式请求（`follow=true`）：接口先返回当前 `tailLines` 行历史，随后持续返回新增；前端持续追加渲染并自动滚动到底部
4. 新日志不断追加，级别着色渲染

### 流程 2：暂停 / 开启自动刷新（暂停不断流 + 缓存续接）

1. 用户点击暂停按钮 → **底层请求不关闭**、流继续接收；前端停止向视图追加、不再自动滚动，保留已有内容；暂停期间到达的增量写入内存缓存（带上限，见 Business Rules）
2. 再次点击（开启）→ 把缓存的增量按顺序 append 到已有日志之后，恢复继续跟随后续增量（无需重载、无重复）
3. 若暂停时长/缓存超过上限 → 丢弃最旧的缓存增量（仅影响暂停期间累积的部分），开启后从保留的缓存续接

### 流程 3：切换日志来源

1. 用户切换来源开关到「容器内文件」→ 展示 `filePath` 输入框
2. 用户输入文件路径并点击确定 → 以 `source=file` + 输入的 `filePath` 重新加载
3. 切回「标准输出」→ 隐藏 `filePath` 输入框，以默认 source 重新加载
4. 切换来源时清空当前内容并重新拉取（见 Business Rules）

### 流程 4：标记分隔线

1. 用户点击旗子图标 → 在当前最新一条日志下方插入一条分隔线
2. 之后到达的新日志渲染在分隔线下方，便于区分"标记时刻之后新增"的日志
3. 再次点击 → 分隔线移动到当前最新一条之后（同一时刻仅一条标记线）【待确认：是否允许多条】

### 流程 5：搜索 / 筛选

1. 用户输入关键字 → 内容区仅展示命中行（高亮命中片段）【待确认：前端过滤 or 接口】
2. 用户选择状态/级别筛选 → 内容区仅展示对应级别日志

## Business Rules

- **默认状态**：来源=标准输出（不传 `source`）、自动刷新=开启（`follow=true`）
- **来源与接口映射**：标准输出→不传 `source`；容器内文件→`source=file`，并携带用户在 `filePath` 输入框输入的路径
- **文件路径生效时机**：来源=文件时展示 `filePath` 输入框，用户输入后点击确定才以该路径加载；未输入路径时不发起 file 来源请求
- **自动刷新与接口映射**：开启→以 `follow=true` 建立流式请求并渲染增量；暂停→**不关闭请求**，前端停止渲染并把增量写入缓存，开启后 append 缓存并继续渲染
- **暂停缓存上限**：暂停期间的增量在内存中缓存，设上限（**默认按时间窗 3 分钟**，可配置；超限丢弃最旧缓存增量）；仅在停留于日志页面时保持，离开页面/关闭 Drawer/切换容器则中止请求并清空
- **固定 tailLines**：每次建立日志流都指定一个固定 `tailLines`，接口返回"当前 `tailLines` 行历史 + 请求后续新增"，前端据此渲染历史尾部并继续跟随增量
- **流式响应特性**：`follow=true` 时接口为长连接流式响应，不会主动结束；前端以流方式消费。**当前 HTTP 流式（fetch `ReadableStream`）接口存在问题，后续拟改造为 SSE**——传输层方案未定，暂停缓存/续接的具体实现待方案确定后落地
- **切换重置**：切换容器、切换来源、Drawer 关闭 / 离开日志页面均需中止当前流、清空已渲染内容与暂停缓存；重新加载时以固定 `tailLines` + `follow=true` 单条请求拉取
- **标记线**：纯前端视觉分隔，不影响数据请求；不随日志清空持久保留
- **级别着色**：按行首日志级别关键字着色（INFO/WARN/ERROR/DEBUG），级别解析规则见 Open Questions

## Edge Cases

- 容器未启动 / 无日志：内容区展示空状态占位
- 流式连接断开（网络中断 / 服务端关闭）：展示中断提示，提供重连入口，暂停态标识清晰
- 日志量极大：需限制前端保留行数（滚动缓冲上限），超出后丢弃最旧行以防内存膨胀【待确认上限】
- `source=file` 但 `filePath` 输入为空：不发起请求，输入框提示需填写路径
- `source=file` 且 `filePath` 指向不存在/无权限文件：展示接口返回的错误提示
- 暂停缓存超限：暂停期间增量超过缓存上限（默认 3min 时间窗）→ 丢弃最旧缓存增量，开启后从保留部分续接，UI 可提示"部分暂停期间日志已丢弃"
- 暂停期间切换容器：视为离开当前流，中止请求并清空缓存，以新容器重新加载（默认恢复为跟随）
- 搜索无命中：内容区展示"无匹配日志"空态，不影响底层流
- Init 容器 / 已终止容器：可能仅有历史日志、无增量，follow 应优雅结束

## API 依赖

| 接口                                    | 位置                             | 用途                    |
| --------------------------------------- | -------------------------------- | ----------------------- |
| `runtimeResourceApi.getContainerLogs()` | `src/api/runtimeResource.ts:167` | 拉取历史日志 + 流式跟随 |

请求参数（`ParamsGetContainerLogs`）：

- `appEnvID` / `clusterId` / `podName` / `containerName`：定位容器（来自 Drawer 上下文）
- `source`：来源，`file`=文件，不传=标准输出 → 来源开关
- `follow`：固定为 `true` 建立跟随流；暂停为前端行为（停止渲染 + 缓存），不改变请求
- `tailLines`：**每次固定指定**，接口返回"当前 `tailLines` 行历史 + 请求后续新增"
- `headLines`：返回最前 N 行（本期未用）
- `previous`：上一个容器实例日志（本期是否用见 Open Questions）
- `filePath`：`source=file` 时容器内文件路径，来自用户在 `filePath` 输入框输入并确定的值

响应：纯文本日志，每行一条；`follow=true` 为不结束的长连接流。

> ⚠️ **传输层未定（未完成）**：现有 HTTP 流式（fetch `ReadableStream`）接口存在问题，后续将尝试改为 **SSE**。暂停缓存/续接、断线重连等实现依赖最终传输层方案，方案确定前本需求与 plan 保持未完成，不锁定具体实现。
