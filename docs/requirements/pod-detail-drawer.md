# Feature: Pod 详情抽屉

> 状态：已实现（2026-07-25，plan `docs/plans/2026-07-25-pod-detail-drawer-plan.md`；日志/终端内容渲染后置）
> 真源修正（2026-07-25）：经核对 `src/interface/entities/pod.ts`，`ContainerPort {name,port,protocol}`、`VolumeMount {name,mountPath,type,readOnly,...}`、`EnvVar {name,value}` **均已在实体中定义**。故端口/挂载表格及环境变量的 名称/值 按真实字段渲染；仅"环境变量来源类型"、"版本/暴露-ENS"仍为数据缺口占位。
> 真源修正（2026-07-29）：`Container.lastTermination {reason,exitCode,startedAt,finishedAt}` 已在实体中定义，"上一次终止"区块改为按真实字段渲染（有终止记录时展示，否则隐藏），不再是数据缺口。
> 来源：Figma 设计稿「工作负载-抽屉-详细信息（支持收起）」
> 父需求：docs/requirements/pod-list-content-area.md（从 Pod 列表操作列"详情"图标点击打开）

## Goal

实现 Pod 详情抽屉（Drawer），从工作负载页面 Pod 列表的操作列点击"详情"图标打开。抽屉以右侧面板形式展示单个 Pod 的完整信息，包括 Pod 概要、所属关系、基本信息和所有容器的详细信息。

## Overall Drawer Layout

抽屉宽度 980px，占屏幕右侧，背景白色，`box-shadow: 0px 2px 20px 0px rgba(0,0,0,0.2)`。

整体从上到下分为四大区域：

```
┌─ 标题栏 ──────────────────────────────────────┐
│ Pod名称 [状态Tag]          [操作图标] [新窗][✕] │
├─ 归属信息 ────────────────────────────────────┤
│ 应用 | 集群 | 工作负载                          │
├─ Pod 基本信息卡片（可收起）───────────────────┤
│ Pod IP / 节点 IP / 版本 / 重启次数 / 存活时间   │
│ / 暴露                                      │
├─ 容器区域 ────────────────────────────────────┤
│ [容器1 Tab] [容器2 Tab] [容器3 Tab] ...        │
│ ┌─ [详细信息] ──────────────────────────────┐ │
│ │ 基本信息 │ 端口 N │ 挂载 N │ 环境变量 N    │ │
│ │ 上一次终止                                │ │
│ └──────────────────────────────────────────┘ │
│ ┌─ 日志 ───────────────────────────────────┐ │
│ │ [标准|文件] [筛选] [搜索]  [暂停][标记][窗][全屏] │ │
│ │ [日志内容区域 — 本期占位]                  │ │
│ └──────────────────────────────────────────┘ │
│ ┌─ 终端 ───────────────────────────────────┐ │
│ │ Shell [current ▼] [连接] [清屏][窗][全屏]   │ │
│ │ [终端内容区域 — 本期占位]                  │ │
│ └──────────────────────────────────────────┘ │
│ ┌─ 事件 ───────────────────────────────────┐ │
│ │ [级别 Select] [搜索 Input]                │ │
│ │ 级别 | 原因 | 对象 | 时间 | 消息           │ │
│ │ [分页]                                    │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

## In Scope

### 1. 标题栏（DrawerTitleBar）

单行左右布局：

```
┌──────────────────────────────────────────────────────────┐
│ ranking-inference-5f6b9-zm9vn [运行中]  [详情][日志][锤][⋮] │ [新窗口] [✕] │
│ ←── Pod 名称 + 状态（左对齐）──→   ←─ 操作图标 ─→       ←─ 通用按钮 ─→ │
└──────────────────────────────────────────────────────────┘
```

| 位置      | 内容                | 说明                                                            |
| --------- | ------------------- | --------------------------------------------------------------- |
| 左侧      | Pod 名称 + 状态 Tag | 名称 20px medium `semantic.text.primary`，Tag 展示 Pod 运行状态 |
| 左侧-操作 | 操作图标组          | 详情、日志、删除/重建、更多（⋮），与列表操作列一致              |
| 右侧      | 通用按钮            | 分隔线 + 新窗口打开图标 + 关闭（✕）图标                         |

### 2. 归属信息（OwnershipInfo）

单行展示 Pod 的归属关系，12px 文字，标签-值对用竖线分隔：

```
应用: 应用名称占位 │ 集群: tokyo-gcp │ 工作负载: tokyo-gcp
```

| 字段     | 标签样式                         | 值样式                         |
| -------- | -------------------------------- | ------------------------------ |
| 应用     | 12px `semantic.text.placeholder` | 12px `semantic.text.secondary` |
| 集群     | 同上                             | 同上                           |
| 工作负载 | 同上                             | 同上                           |

### 3. Pod 基本信息卡片（PodBasicInfoCard）

居中显示 Pod 的核心指标，可收起/展开。默认展开。

**卡片容器**：`radius.xl`（12px），`semantic.bg.page`（#F5F7FA），内边距 16px/20px。

**展开态内容**（两行四列）：

| 行    | 左1                      | 左2                          | 右1                | 右2               |
| ----- | ------------------------ | ---------------------------- | ------------------ | ----------------- |
| 第1行 | **Pod IP**: `10.31.15.7` | **节点 IP**: `192.168.10.18` | **版本**: `v2.3.1` | **重启次数**: `7` |
| 第2行 | **存活时间**: `3d`       | **暴露**: `ENS`              | —                  | —                 |

- 重启次数颜色编码（同 pod-list-content-area.md 规则）：**≥6 红色** (`error-6`), **3-5 橙色** (`warning-6`), **≤2 黑色** (`semantic.text.primary`)
- 标签 14px `semantic.text.tertiary`，值 14px `semantic.text.secondary`，IP 使用 Menlo 字体
- 字段来源：Pod IP → `podIp`，节点 IP → `hostIp`，重启次数 → `restarts`，存活时间 → 由 `creationTimestamp` 计算
- ⚠️ **数据缺口**：**版本**（Pod 无对应版本字段）、**暴露 / ENS**（接口未返回服务暴露字段）本期以占位符展示，待接口补充后接入（见文末数据缺口汇总）
- 收起按钮：白色圆角胶囊按钮（48×18px, `radius.xl3`），文字"收起" + 向上箭头，居中定位在卡片底部边界上

### 4. 容器区域（ContainerArea）

Pod 下所有容器以 **Tab 页** 形式展示，每个容器一个 Tab。选中容器后，内部展示该容器的**子 Tab**：详细信息 / 日志 / 终端 / 事件。

**容器 Tab 栏样式**：

- 背景 `semantic.bg.default`（#F0F1F5），`radius.xl2`（16px），内边距 4px
- 选中 Tab：白底 + 圆角 + 容器名称（14px medium）+ 容器类型 Badge（主容器 / Sidecar / Init / 普通，10px）
- 未选中 Tab：容器名称（14px medium `semantic.text.tertiary`）+ 容器类型 Badge（灰字 `semantic.text.tertiary`）
- 容器名称前有 6px 圆点，选中时绿色，未选中时灰色

#### 4a. 子 Tab 栏

当前选中容器的子 Tab：**详细信息** | 日志 | 终端 | 事件。选中态底部有 3px 黑色指示条。

#### 4b. 容器"详细信息"Tab

> 本需求文档涵盖"详细信息"、"日志"、"终端"和"事件"子 Tab。四个子 Tab 全部在本期范围内。

详细信息包含以下 **5 个内容区块**，每个区块左侧有绿色竖条（3px, `radius.sm`, `rgba(114,232,177,1)`）+ 标题，区块间距 48px。

##### 4b-1. 基本信息

两行四列 + 一行三列的网格布局：

| 行    | 字段                                                     | 说明                                                                                                                                  |
| ----- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 第1行 | **状态**: 运行中 (Tag)                                   | Tag 组件，样式与列表一致                                                                                                              |
| 第1行 | **就绪**: 是                                             | Boolean 文本                                                                                                                          |
| 第1行 | **重启次数**: `0`                                        | 颜色编码规则同 3 节                                                                                                                   |
| 第1行 | **存活时间**: `8d`                                       | dayjs 计算 duration                                                                                                                   |
| 第2行 | **镜像**: `registry.internal/...` + Badge `IfNotPresent` | 镜像地址 14px `semantic.text.primary`，拉取策略 Badge（10px, `radius.xl3`, `semantic.bg.component.hover`, `semantic.text.secondary`） |
| 第3行 | **启动命令**: `/app/server --config=...`                 | 14px `semantic.text.primary`，可能很长需要截断或 tooltip                                                                              |

**资源用量**（基本信息区块内的子区域，并排三列，竖线分隔）：

| 资源 | 展示内容                                         | 说明                                                                                                                                                                                            |
| ---- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CPU  | 图标 + `7.2c/8c/16c` + 进度条 + `使用率%`        | 格式：实际使用/request/limit；进度条 120px；高负载时百分比红色 (`error-6`)，正常黑色                                                                                                            |
| 内存 | 图标 + `29.44Gi/32Gi/9.1Gi` + 进度条 + `使用率%` | 同上                                                                                                                                                                                            |
| GPU  | 厂商图标 + 型号/Profile + 数量                   | 仅读取 `resourceLimits.gpus`：按 `vendor` 选择英伟达、华为昇腾或百度昆仑芯图标，左侧两行展示 `model` 和 `profile`，右侧展示 `x<count>`；`others` 不参与 GPU 展示；**该容器无 GPU 时不显示此列** |

##### 4b-2. 端口

标题格式：**端口 <灰色 N>**（N 为该容器的端口总数计数值，灰色为 `semantic.text.tertiary`）。

标题右侧有"复制全部IP:PORT"按钮。

表格列：

| 列       | 说明                               | 数据来源                        |
| -------- | ---------------------------------- | ------------------------------- |
| 端口类型 | 端口协议类型                       | `containers[].ports[].protocol` |
| 端口名称 | 端口 name                          | `containers[].ports[].name`     |
| 端口号   | 端口号                             | `containers[].ports[].port`     |
| 操作     | 复制图标，点击复制该端口 `IP:PORT` | —                               |

> `ContainerPort {name, port, protocol}` 已在实体中定义，按真实字段渲染。

##### 4b-3. 挂载

标题格式：**挂载 <灰色 N>**（N 为该容器的挂载卷总数计数值）。

表格列：

| 列       | 说明                                        | 数据来源                                                |
| -------- | ------------------------------------------- | ------------------------------------------------------- |
| 类型     | 挂载卷类型（config / secrets / data 等）    | `containers[].volumeMounts[].type`                      |
| 挂载路径 | 容器内挂载路径                              | `containers[].volumeMounts[].mountPath`                 |
| 来源     | 挂载来源（ConfigMap: xxx / Secret: xxx 等） | `containers[].volumeMounts[].configMap?.name` / `.name` |
| 操作     | 权限文本（只读 / 读写）                     | `containers[].volumeMounts[].readOnly`                  |

> `VolumeMount {name, mountPath, type, readOnly, subPath, configMap...}` 已在实体中定义，按真实字段渲染。

##### 4b-4. 环境变量

标题格式：**环境变量 <灰色 N>**（N 为该容器的环境变量总数计数值）。

表格列：

| 列   | 说明                                              | 数据来源                                                 |
| ---- | ------------------------------------------------- | -------------------------------------------------------- |
| 名称 | 环境变量 key                                      | `containers[].env[].name`                                |
| 值   | 环境变量 value                                    | `containers[].env[].value`                               |
| 来源 | 来源类型（Field / ConfigMap / Secret / 直接赋值） | ⚠️ 接口 `containers[].env[]` 未定义来源类型子字段，暂占位 |

> `EnvVar {name, value}` 已在实体中定义，名称/值按真实字段渲染；仅"来源类型"为数据缺口占位。

##### 4b-5. 上一次终止

只在容器有终止记录时显示，首次启动的容器隐藏此区块。

两行两列布局：

| 行    | 左列                                | 右列                                |
| ----- | ----------------------------------- | ----------------------------------- |
| 第1行 | **原因**: `Completed`               | **退出码**: `0`                     |
| 第2行 | **开始时间**: `2026.06.04 04:20:06` | **结束时间**: `2026.06.04 04:20:06` |

> **数据来源**：`containers[].lastTermination`（`reason` / `exitCode` / `startedAt` / `finishedAt`，K8s lastState.terminated 语义）已在实体中定义，按真实字段渲染。仅当 `lastTermination` 含有效终止记录（`reason` / `startedAt` / `finishedAt` 任一非空）时展示，首次启动、无终止记录的容器隐藏此区块（Business Rule 6）。时间按 `YYYY.MM.DD HH:mm:ss` 格式化。

## Out Of Scope

- 日志和终端的具体内容渲染和交互（本期仅占位）
- Pod 操作按钮的具体业务逻辑（详情已在标题栏展示，其余操作行为后续定义）
- 新窗口打开按钮的具体行为
- 移动端适配

## Main User Flows

```
用户在 Pod 列表操作列点击"详情"图标
  → 右侧滑出 Pod 详情抽屉
  → 抽屉上方显示 Pod 名称、状态、归属信息和基本信息卡片
  → 下方容器 Tab 默认选中第一个容器，展示"详细信息"子 Tab
  → 用户可切换容器 Tab 查看不同容器的详细信息
  → 用户点击关闭按钮或抽屉外区域关闭抽屉
```

```
用户点击基本信息卡片的"收起"按钮
  → 基本信息卡片折叠为仅 Pod IP + 其他摘要行
  → 按钮文字变为"展开"，箭头向下
用户再次点击
  → 基本信息卡片恢复完整展开态
```

```
用户在容器子 Tab 中点击"事件"
  → 切换至事件列表视图
  → 顶部显示级别筛选和搜索栏
  → 表格展示该容器的事件，按时间倒序排列
  → 用户可通过级别 Select 过滤不同级别的事件
  → 用户可在搜索框中按原因、消息、对象搜索
  → 翻页浏览更多事件
```

```
用户在容器子 Tab 中点击"日志"
  → 切换至日志视图
  → 顶部显示输出模式切换（标准输出 / 文件输出）、筛选栏和搜索栏
  → 右侧显示暂停、标记、在窗口查看、全屏操作按钮
  → 下方日志内容区域展示日志（本期占位）
  → 点击"暂停"按钮，日志停止滚动/刷新，按钮切换为"开始"
  → 再次点击"开始"，日志恢复滚动/刷新，按钮切换回"暂停"
  → 点击"全屏"按钮，日志区域扩展至全屏，按钮切换为"退出全屏"
  → 再次点击"退出全屏"恢复原始布局
```

## Business Rules

1. 抽屉从右侧滑入，宽度固定 980px，遮盖页面内容区（非 push）
2. 容器 Tab 顺序：将 `containers` 和 `initContainers` 合并后按 `type` 字段排序展示：MAIN（主容器）→ NORMAL（普通容器）→ SIDECAR（Sidecar）→ INIT（Init）
3. 基本信息卡片展开/收起状态仅影响当前打开的抽屉实例
4. GPU 资源用量列：容器无 GPU 时不显示，有 GPU 时不同品牌展示不同图标
5. 端口/挂载/环境变量表格的标题中计数值（N）使用灰色（`semantic.text.tertiary`）
6. "上一次终止"区块：仅容器有终止记录时展示；首次启动的容器不显示
7. 所有表格数据来自接口，不使用硬编码占位
8. 日志输出模式默认"标准输出"，切换为"文件输出"后日志内容需重新拉取
9. "暂停"和"全屏"按钮为 toggle 按钮：暂停 ↔ 开始，全屏 ↔ 退出全屏
