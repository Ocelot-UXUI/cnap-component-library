# AI Agent 能力增强 - 需求列表

> 来源：2026-06-12 AI Debug/AI Chat 现有机制分析与 XState 方案讨论

## P0

### REQ-AI-01: 上下文信息量过少

- **问题**：当前 `usePageContext` 只生成一句话摘要（"当前路由: X。可操作: A、B。可输入参数: C、D"），LLM 无法理解业务规则、操作后果、字段校验、可选值范围
- **仍需设计**：需结构化暴露机器状态（当前状态、可用事件、guard 条件）给 LLM，替代当前一句话摘要
- **状态**：待评估

### REQ-AI-02: 无法感知页面动态状态

- **问题**：表单已填入的值、列表当前数据、异步操作进度不在上下文中
- **仍需设计**：表单值等业务数据存储在机器 context 中，可实时读取
- **状态**：待评估

### REQ-AI-03: 执行结果回传过于简陋

- **问题**：`agentLoop` 固定返回 `'执行成功'` 或错误信息，LLM 拿不到新状态、API 响应数据，无法基于结果做后续决策
- **仍需设计**：需设计结构化的执行结果回传（新状态值、context 变更、API 响应），替代固定返回"执行成功"
- **状态**：待评估

### REQ-AI-04: 工具定义来自 capabilities 注册表

- **问题**：当前 tools schema 从 `capabilities/` 自动生成，大部分能力是 mock，且与未来 XState 事件体系脱节
- **仍需设计**：需设计 tool 注册机制，从状态机事件定义自动生成 JSON Schema（注意复杂类型的转换精度）
- **状态**：待评估

### REQ-AI-05: 机器定义到 LLM 可消费格式的转换

- **问题**：XState definition 是 TypeScript 对象，LLM 需要可理解的 JSON 结构
- **仍需设计**：XState definition → LLM 可理解的 JSON 结构，需设计转换层和扩展属性（如事件描述、参数说明等）
- **状态**：待评估

### REQ-AI-06: 不是所有状态都适合建模

- **问题**：路由跳转、标签切换、滚动定位等纯视图操作走状态机是过度设计
- **方案**：统一路由链接管理层（`src/routes/` + ESLint 规则），将路由跳转等纯视图操作聚合为全局对象暴露给 LLM
- **详细需求**：`docs/requirements/route-link-management.md`
- **状态**：已完成

### REQ-AI-14: 路由信息暴露给 LLM（← 下一步）

- **前置依赖**：REQ-AI-06（已完成）
- **问题**：`src/routes/` 中统一管理的路由信息如何传递给 LLM，使 LLM 能知道如何导航到任意业务页面
- **方案**：扩展 Route 接口增加 path 字段，新增 RouteMeta + getRouteMetas()，路由元数据注入 system prompt，新增 navigate 工具替代 capabilities
- **详细需求**：`docs/requirements/route-context-for-llm.md`
- **状态**：已完成

## P1

### REQ-AI-07: 依赖 data-ai-* 标记

- **问题**：`usePageContext` 扫描依赖源码中的 `data-ai-*` 自定义属性，入侵源码、维护成本高
- **仍需设计**：需评估在 XState 方案下哪些场景仍需 DOM 兜底，标记体系是保留、裁剪还是替换
- **状态**：待评估

### REQ-AI-08: 无确认/追问机制

- **问题**：危险操作（删除、部署、审批）不经用户确认就直接执行
- **仍需设计**：需设计 LLM 交互协议，在特定操作执行前经用户确认
- **状态**：待评估

### REQ-AI-09: 日志只有 console.log

- **问题**：所有执行日志用 console 输出，无法结构化收集或展示给用户
- **仍需设计**：需结构化日志（步骤级输入输出、执行时间、状态快照），功能才可迭代改进
- **状态**：待评估

### REQ-AI-10: jotai 管的简单状态对 LLM 不透明

- **问题**：jotai 管理的状态不被 XState 覆盖，LLM 看不到
- **仍需设计**：需评估 jotai 状态中哪些对 LLM 决策有影响，设计暴露机制或统一收敛到状态机
- **状态**：待评估

## P2

### REQ-AI-11: 错误处理无恢复（agentLoop 层）

- **问题**：步骤执行失败后无重试、跳过或降级策略
- **仍需设计**：需设计降级策略和兜底话术（如 guard 拒绝后引导用户补充信息）
- **状态**：待评估

### REQ-AI-12: 多机器协调

- **问题**：一个业务操作可能跨多个状态机
- **仍需设计**：跨状态机操作时 LLM 需知道调用顺序和上下文传递方式
- **状态**：待评估

### REQ-AI-13: 机器实例生命周期管理

- **问题**：弹窗级实例 vs 全局单例、多实例并发隔离
- **仍需设计**：需设计状态机实例的创建、销毁和隔离策略
- **状态**：待评估
