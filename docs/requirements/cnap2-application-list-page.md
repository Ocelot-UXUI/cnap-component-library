# Feature: 应用列表页面（应用卡片）

> 状态：未完成（待补充）——已澄清搜索/筛选/收藏/分页/卡片布局/默认环境等要点，仍待进一步补充（含点击落点路由 B2、无环境展示形态）后进入实现
> 来源：`docs/input/source-meeting-cnap2-CNAP_2.0应用列表-需求评审记录.md` + 页面结构补充说明（2026-08-11）
> 路由：`/applications`

## Goal

实现 CNAP 2.0 应用列表页面，以卡片形态展示当前账号下的应用，支持按名称搜索、按应用类型 / 环境 / 用户标签筛选定位应用，并支持从卡片直接进入应用、切换环境、收藏应用等操作。

本文档当前切片聚焦**应用卡片展示信息与卡片操作**；新建应用向导、应用模板、应用设置等页面不在此范围。列表（表格）视图的展示内容不在此范围（见 Out Of Scope）。

## 页面整体结构

| 区域 | 说明 |
| ---- | ---- |
| A. 页头 | 左侧标题"应用列表"；右侧按钮区："新建应用"（主按钮）+ "从模板新建" |
| B. 筛选区 | 按名称搜索；按应用类型（单选）、环境（单选）、用户标签（多选）筛选；各条件可叠加 |
| C. 展示形态切换区 | 内容区右侧提供卡片 / 列表两种展示形态切换按钮；本切片仅实现卡片视图（默认卡片），点击列表视图暂不响应（忽略态），列表视图内容留待后续切片 |
| D. 内容区 | 应用卡片列表（当前切片重点，见 In Scope） |
| E. 面包屑 | 应用列表页面包屑导航显示应用选择框，提示文案"请选择应用"（文案来源为需求评审记录）；交互与 `cnap2-breadcrumb-context-selectors.md`（Draft，待其定稿）对齐 |

> 页头"新建应用 / 从模板新建"仅提供入口，向导流程不在本切片（见 Out Of Scope）。

## In Scope（当前切片）

### 应用卡片布局

卡片内容分左右两部分，左右对齐：

- **左侧（头像 + 名称 + 系统标签 + 用户标签）**
  - 最左侧展示应用头像
  - 头像右侧为应用名称，名称下一行展示系统标签（平台生成）
  - 用户标签展示在卡片名称下方标签区域，可点击进入筛选
  - 应用描述展示在名称 / 标签区域下方
  - 头像、名称、系统标签、用户标签、描述共同构成左侧整体
- **右侧（操作按钮区）**
  - 卡片右上角放置收藏按钮，与左侧整体对齐（设置入口留待后续切片）

### 应用卡片展示信息

1. **应用头像**：接口暂无头像字段，先展示占位头像（后续接口补充后再替换）
2. **应用名称**：展示 `displayName`（缺省回退 `name`）
3. **应用描述**：卡片上展示应用描述
4. **系统标签**：平台生成（非用户自定义），展示应用属性（负载类型、技术栈等），展示在应用名称下一行，仅展示、不可点击
5. **用户标签**：用户自定义标签（`userLabels`），展示在卡片名称下方标签区域，点击可进入按该标签的筛选
6. **环境列表**：列出应用的全部环境，按接口返回顺序展示（前端不做分组 / 排序）
7. **最近变更**：按接口返回展示每个环境的最近变更信息：部署人、变更时间、所属环境、变更类型
8. **收藏状态**：由 `isCollected` 决定，通过右上角收藏按钮体现

### 卡片操作

1. **点击卡片** → 进入该应用（应用工作区）；默认环境取 `defaultApplicationEnvironmentId`，默认落地页由独立的工作区需求定义（落点路由 B2 悬置，本切片暂不实现跳转）
2. **点击环境项** → 直接切换到目标"应用 + 环境"（一次点击同时切换应用与环境）（落点路由 B2 悬置，本切片暂不实现跳转）
3. **点击用户标签** → 自动进入按该标签的筛选（与筛选区联动，多选可叠加）
4. **收藏 / 取消收藏** → 点击卡片右上角收藏按钮，状态随 `isCollected` 更新，重复操作幂等
5. **交互注意**：点击环境项、收藏按钮时需阻止事件冒泡，避免同时触发卡片点击进入应用（接口文档 2.6 约定）

> 说明（2026-08-11）：卡片上系统标签（平台生成，仅展示）与用户标签（可点击筛选）并存；"点击标签进入筛选"仅针对用户标签（`labelIds` 支持多选），系统标签无筛选参数、不可点击。

## Main User Flows

1. **浏览与进入应用**：进入应用列表页 → 查看应用卡片（头像 / 名称 / 系统标签 / 描述 / 环境 / 最近变更 / 收藏状态）→ 点击卡片进入应用工作区
2. **按条件定位应用**：在筛选区按名称搜索，或按应用类型（单选）/ 环境（单选）/ 用户标签（多选，可叠加）筛选 → 列表按条件收敛 → 点击卡片进入应用
3. **按标签筛选**：点击卡片上的用户标签 → 自动进入按该标签的筛选结果（该标签在筛选区处于选中态，可与其他条件叠加）
4. **快速切换应用 + 环境**：点击某应用卡片上的环境项 → 直接进入目标应用的目标环境
5. **收藏 / 取消收藏应用**：点击卡片右上角收藏按钮 → 状态切换（`isCollected`），重复操作幂等

## Business Rules

1. **点击卡片进入应用工作区**：默认落地页规则由独立的工作区需求定义，本需求不承载"上次访问记录"逻辑
2. **默认环境**：直接取 `defaultApplicationEnvironmentId`（后端计算，默认即生产环境）；后端保证恒有值，前端不做缺失兜底
3. **环境展示**：卡片上环境列表按接口返回顺序展示，前端不做分组 / 排序；按环境筛选只收敛应用集合，卡片内环境列表仍按接口直出、不收敛
4. **系统标签**：平台生成（`systemLabels`，字符串数组），展示在应用名称下一行，仅展示、不可点击，用户不可自定义
5. **筛选**：应用类型单选、环境单选、用户标签多选；搜索 + 类型 + 环境 + 标签各条件可同时生效；点击卡片用户标签进入筛选后，该标签在筛选区处于选中态，可与其他条件叠加
6. **最近变更内容**：按接口返回展示最近变更的部署人、时间、环境、变更类型，前端不做筛选；变更时间按 `YYYY-MM-DD HH:mm:ss` 展示（dayjs）
7. **筛选数据源**：筛选区的应用类型 / 环境 / 用户标签选项由 `GET /rest/v1/accounts/{accountID}/applications/filter-options` 初始化；`applicationTypes` 取应用实际使用的 `application_type.category` 去重后按名称升序，环境与用户标签按 ID 升序；无数据时对应字段返回空数组。`applicationTypes` 值原样透传为 `type` 参数，不做大小写转换。筛选区的环境选项为公共环境（`environments[].id`），与卡片环境列表的应用环境（`applicationEnvironmentId`）为不同 ID 值域——前者仅用于列表筛选参数 `environmentId`，后者用于点击环境项跳转
8. **收藏**：收藏状态由 `isCollected` 决定（后端按当前请求用户判断，列表接口建议携带 `x-baidu-int-username` 请求头用于收藏状态判断，收藏 / 取消收藏接口必填）；收藏 / 取消收藏调用 `POST / DELETE /rest/v1/applications/{applicationID}/collection`，重复操作幂等；收藏按钮点击后按接口返回更新 `isCollected`。`x-baidu-int-username` 通过包装层注入：先获取当前用户名（`window.__icloud__?.username`，必要时异步 `/api/home/v2/login-info`），再写入调用请求头（需合并公共 headers，避免覆盖 `x-region` / `x-account-id`）
9. **ID 字符串约定**：接口响应中的业务 ID（含应用 id、accountId、applicationEnvironmentId 等）统一为字符串
10. **分页**：应用列表默认每页 10 条（pageSize=10），页码从 1 开始；翻页或筛选条件变化时重新请求

## Roles / Permissions

- 页面不做前端级权限控制，遵循平台既有鉴权与数据接口权限，无额外角色分支。

## Edge Cases

- 应用无环境：卡片不展示环境列表（空态表现待定，见 Open Questions）
- 应用无描述 / 无系统标签 / 无用户标签：卡片对应区域留空或隐藏
- 无最近变更记录（`recentChanges` 为空）：卡片不展示"最近变更"区域；仅部分环境有记录时，按接口返回逐条展示，不为缺失环境占位
- 筛选 / 搜索无结果：展示空态
- 收藏接口失败：提示失败并保持原收藏状态，可重试
- 分页边界：当前页超出总页数时回落至末页并重新请求

## Open Questions

- 应用没有任何环境时，卡片上环境区域的展示形态（隐藏 / 空态文案）
- 点击卡片 / 环境项进入应用工作区的落点路由（B2，悬置）：本切片暂不实现跳转，后续切片确定落点后接续
