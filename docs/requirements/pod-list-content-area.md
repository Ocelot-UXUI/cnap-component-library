# Feature: Pod 列表内容区域

> 状态：已实现（2026-07-25，plan `docs/plans/2026-07-25-pod-list-content-area-plan.md`）
> 来源：Figma 设计稿 + 用户指令 + 产品设计文档 + 需求评审会议记录
> 父需求：docs/requirements/workloads-page.md（子需求 2+3）
> 范围变更（2026-07-25，用户指示）：**本切片直接对接真实 API（`runtimeResourceApi.getPods/getWorkloadGroups/getRuntimeSummary`、`runtimeOperationApi.getOperations`），不使用 mock 数据。**

## Goal

实现工作负载页面中 Pod 列表内容区域，替换当前 `ContentAreaPlaceholder` 占位。该区域作为工作负载页面的核心内容区，支持按工作负载组分组展示 Pod 列表，提供筛选、搜索、视图切换、全展开/全折叠等交互能力。

## In Scope

**整体容器样式（来自 Figma 工作负载-页面）：**

| 宽度     | 1208px（相对于主内容区左右各内缩 24px） |
| 背景     | 透明（继承页面 `semantic.bg.page`）     |
| 垂直排列 | flex column，各区域从上到下排列         |

**各区域间距（来自 Figma）：**

### 1. 内容区标题栏（PodContentHeader）

单行左右布局，作为 Pod 列表内容区的头部：

```
┌──────────────────────────────────────────────────────────┐
│ Pod列表                  [收起] [展开] [刷新] [详细|精简]  │
│ ←── 标题（左对齐）──→      ←── 操作图标组（右对齐）────→ │
└──────────────────────────────────────────────────────────┘
```

| 位置 | 内容       | 说明                                                                         |
| ---- | ---------- | ---------------------------------------------------------------------------- |
| 左侧 | 标题文字   | "Pod列表"，20px medium `semantic.text.primary`，使用 `typography.heading.h3` |
| 右侧 | 操作图标组 | 5 个图标按钮，从左到右：收起全部 Pod、展开全部 Pod、刷新、详细模式、精简模式 |

**交互规则：**

- 收起/展开：控制所有 group 下的表格行折叠/展开，默认全部展开
- 详细/精简模式切换：使用分段式按钮（segmented toggle），默认详细模式
- 刷新：触发 Pod 列表数据重新加载

### 2. 筛选操作区（PodFilterBar）

位于工具栏下方，单行左右对齐布局：

```
┌──────────────────────────────────────────────────────────────────────┐
│ [状态 Select] [屏蔽与解除屏蔽 Select] [搜索 Input]   快捷筛选 [全][正][异][屏] │
│ ←────────── 筛选表单（左对齐）──────────→          ←─ 快捷筛选（右对齐）─→ │
└──────────────────────────────────────────────────────────────────────┘
```

#### 2a. 筛选表单（左侧）

| 表单项         | 组件           | 宽度  | 查询参数  | 清空 | 说明                                                                         |
| -------------- | -------------- | ----- | --------- | ---- | ---------------------------------------------------------------------------- |
| Pod 状态       | Select（多选） | 120px | `status`  | 支持 | 选项来源于 Pod 汇总/列表接口的 `summary.statuses[]`，显示 `中文名（count）`  |
| 屏蔽与解除屏蔽 | Select         | 120px | `blocked` | 支持 | 选项：已屏蔽 / 未屏蔽。`blocked=true` 对应已屏蔽，`blocked=false` 对应未屏蔽 |
| 搜索           | Input.Search   | 256px | `keyword` | 支持 | 按 Pod 名称和 IP 进行模糊搜索                                                |

#### 2b. 快捷筛选（右侧）

标签 "快捷筛选" + 一组芯片式按钮（connected button group），每个按钮显示名称 + 数量计数。计数数据来源：Pod 列表接口 `summary` 字段（`PodStatistics` 结构，含 `totalCount`、`blockedCount`、`statuses[]`）。

| 按钮           | 映射规则                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------- |
| 全部（计数）   | 清除 Pod 状态筛选；计数 = `totalCount`                                                                              |
| 正常（计数）   | 筛选 `Running Ready` + `Completed` + `Terminating` + `Running InPlaceUpdateNotReady`；计数 = 这 4 种状态 count 之和 |
| 异常（计数）   | 筛选所有非正常状态（即状态表中"是否正常"为"否"的全部状态）；计数 = `totalCount` - 正常计数                          |
| 已屏蔽（计数） | 筛选 `blocked=true`；计数 = `blockedCount`                                                                          |

**按钮样式（来自 Figma）：**

- 82px × 32px，按钮组相邻边框重叠（-1px margin）
- 选中态：边框色较深、文字 **medium** 字重（`semantic.text.secondary`）
- 未选中态：边框色较浅、文字 regular 字重（`semantic.text.tertiary`）

#### 2c. 快捷筛选与筛选表单的联动规则

```
┌──────────────────┬──────────────────────────────────────────────┐
│ 用户操作              │ 系统行为                                        │
├──────────────────┼──────────────────────────────────────────────┤
│ 点击快捷筛选按钮      │ 自动在「Pod 状态」Select 中设置对应的值             │
│ （如"正常"）          │ （如 Select 选中"运行中"）                       │
├──────────────────┼──────────────────────────────────────────────┤
│ 手动修改「Pod 状态」   │ 如果当前有快捷筛选按钮处于选中态，取消该按钮的选中    │
│ Select 的值          │ 快捷筛选恢复为无选中状态                           │
├──────────────────┼──────────────────────────────────────────────┤
│ 点击"全部"           │ 清除「Pod 状态」Select 的选中值（不过滤状态）          │
└──────────────────┴──────────────────────────────────────────────┘
```

**关键约束：**

- 快捷筛选始终是**单选**（同一时刻最多一个按钮选中），但每个按钮可映射到 Pod 状态 Select 中的**多个值**（1:N 映射）
- "Pod 状态" Select 支持多选
- 联动仅作用于 Pod 状态维度，不影响「屏蔽与解除屏蔽」和「搜索」

### 3. Pod 分组表格（PodGroupTable）

按工作负载组（WorkloadGroup）分组展示 Pod，每个组包含组标题行 + 表格。

#### 3a. 组标题（GroupHeader）

**容器样式（来自 Figma）：**

- 高度 48px，圆角 `radius.xl`（12px），背景 `semantic.bg.page`（#F5F7FA）
- 内边距：上 13px / 右 16px / 下 12px / 左 12px
- 单行 flex 布局，`justify-content: space-between`

**单行左右布局：**

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ▶ Payment-api  [Rollout] │ v1.8.3 等3个版本   运行中⓹  异常❶  已屏蔽❶ │ 共 10 pod  ⋮ │
│ ←────── 组信息（左对齐）───────────→           ←── 状态统计（右对齐）───→              │
└──────────────────────────────────────────────────────────────────────────┘
```

**左侧 — 组信息（从左到右）：**

| 元素          | 样式（来自 Figma）                                                        | 说明                                                        |
| ------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 展开/收起按钮 | 16×16px 三角图标                                                          | 点击切换该组表格的折叠/展开。默认展开（▼），收起时向右（▶） |
| 组名称        | 14px medium `semantic.text.primary`                                       | 工作负载名称，如 `Payment-api`                              |
| 类型标签      | 57×18px，`radius.xl3`（20px），bg #E8E8E8，12px `semantic.text.secondary` | 工作负载类型 Badge，如 `Rollout`、`Deployment` 等           |
| 分隔线        | 1px 宽 × 12px 高，`semantic.border.divider`                               | 分隔组信息与 API 版本                                       |
| API Version   | 14px `semantic.text.tertiary`                                             | 显示 Group 层级的 `currentVersion` 字段内容                 |

**API Version hover 交互：**

当鼠标 hover 至 API Version 文字时，显示一个浮窗（Popover），展示该组下所有 Workload 的版本详情，数据来源为 Group 下的 `Workloads` 数组，每行左右分两列：

| 列   | 说明                          |
| ---- | ----------------------------- |
| 左侧 | `clusterName` — 集群名称      |
| 右侧 | `currentVersion` — 当前版本号 |

**右侧 — 状态统计（从左到右）：**

| 元素     | 样式                                                                                                      | 说明                                        |
| -------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 运行中   | 14px `semantic.text.secondary` + 22×22px 圆角 8px Badge（bg `brand-1` #E6FAF1，文字 `success-6` #00CC6D） | 该组内 Running 状态的 Pod 数量              |
| 异常     | 同上 + Badge（bg `error-1` #FDECEE，文字 `error-6` #E62C4B）                                              | 该组内异常状态的 Pod 数量                   |
| 已屏蔽   | 同上 + Badge（bg `warning-1` #FFF3E0，文字 `warning-6` #F58300）                                          | 该组内已屏蔽的 Pod 数量                     |
| 分隔线   | 1px × 12px，`semantic.border.divider`                                                                     | 分隔状态统计与总数                          |
| 共 N pod | 14px `semantic.text.secondary`                                                                            | 该组 Pod 总数（与分页无关），如 `共 25 pod` |
| ⋮        | 16×16px 三点图标                                                                                          | hover 时显示该组的操作下拉菜单              |

**操作下拉菜单（hover ⋮ 时显示）：**

下拉菜单的操作项由两部分组成：

1. **后端返回的操作**：来自 `operations` 字段（`targetKind: Workload` 或 `None` 的操作），`disabled=true` 时对应项置灰
2. **前端自行拼接的操作**：「工作负载 YAML」由前端自行拼接到操作列表末尾

| 菜单项        | 来源              | 样式                     | 点击行为                                       | 启用条件                       |
| ------------- | ----------------- | ------------------------ | ---------------------------------------------- | ------------------------------ |
| 后端操作列表  | `operations` 字段 | 14×14px 图标 + 14px 文字 | 由各操作定义                                   | `disabled=false` 时可用        |
| 工作负载 YAML | **前端自行拼接**  | 14×14px 图标 + 14px 文字 | 打开页面右侧抽屉，展示该组工作负载的 YAML 配置 | **仅在当前已选择集群时可触发** |

> **为什么"工作负载 YAML"需要选择集群？**：Group（工作负载组）+ Cluster（集群）两个维度才能唯一确定一个 Workload，进而查看对应的 YAML。因此该按钮在用户未选择集群时不可用（置灰）。
>
> 右侧抽屉的实现不在本次需求范围内。
>
> **操作列表拼接规则**：后端 `operations` 字段返回的操作项在前，前端将「工作负载 YAML」拼接到列表末尾。

#### 3b. 表格

| 属性 | 说明                                                                                       |

| 组件 | antd Table                                                                                 |

**快捷批量选择（来自 Figma）：**

Pod 名称列表头左侧有一个小箭头图标。hover 时箭头旋转至**向上**，并在下方弹出 Dropdown，包含以下快捷操作：

| 菜单项       | 样式（来自 Figma）                                                   | 行为                        | 备注     |
| ------------ | -------------------------------------------------------------------- | --------------------------- | -------- |
| 全选本页     | 112×32px，14px `semantic.text.primary`，`radius.lg`（8px），默认白底 | 选中当前页所有 Pod          | --       |
| 全选所有     | 同上，hover 态灰底（#F2F2F2）                                        | 选中该组所有分页的全部 Pod  | 暂时去掉 |
| 反选本页     | 同上                                                                 | 反转当前页的选择状态        | --       |
| 反选所有     | 同上                                                                 | 反转该组所有 Pod 的选择状态 | 暂时去掉 |
| 取消全部选择 | 同上                                                                 | 取消所有已选中的 Pod        | --       |

下拉容器：120×176px，`radius.lg`（8px），白底，4px 内边距，菜单项间距 2px。

**精简模式与详细模式的通用规则：**

| 模式     | 行高                  | 折行                                           |
| -------- | --------------------- | ---------------------------------------------- |
| 精简模式 | 单行                  | 内容不折行，始终保持一行显示                   |
| 详细模式 | 双行（主行 + 扩展行） | 每个单元格下方扩展一行，新增内容在扩展行中显示 |

> 详细模式下，如果某列的扩展行内容为空（即仅单行内容），则该单行内容在垂直轴上**居中显示**。

默认：详细模式。

**表格列定义（从左到右）：**

精简模式的表头和内容参见下方"精简模式表头"列；详细模式在此基础上扩展。

| #  | 精简模式表头 | 详细模式表头变化     | 详细模式扩展行内容                                                                                            |
| -- | ------------ | -------------------- | ------------------------------------------------------------------------------------------------------------- |
| 1  | ☑            | 不变                 | —（单行居中）                                                                                                 |
| 2  | Pod 名称     | → **Pod名称/集群**   | 集群信息                                                                                                      |
| 3  | 状态         | → **状态/容器**      | 就绪容器数 / 总容器数（`readyContainers` / `totalContainers`）                                                |
| 4  | Pod IP       | → **Pod IP/节点 IP** | 节点 IP                                                                                                       |
| 5  | 端口         | 不变                 | 每个端口数据占一行（多端口时多行展示）                                                                        |
| 6  | 服务暴露     | 不变                 | 每个服务暴露数据占一行（多个时多行展示）                                                                      |
| 7  | 重启         | 不变                 | —（单行居中）。hover 重启次数时，Tooltip 显示 `lastStartedAt`                                                 |
| 8  | 存活         | 不变                 | —（单行居中）                                                                                                 |
| 9  | CPU          | 不变                 | 图标 + 使用率百分比。高负载时文字红色（`error-6`），正常黑色（`semantic.text.primary`）                       |
| 10 | 内存         | 不变                 | 图标 + 使用率百分比。高负载时文字红色（`error-6`），正常黑色（`semantic.text.primary`）                       |
| 11 | GPU          | 不变                 | GPU 型号及数量。**该组无 GPU 资源时隐藏整列**                                                                 |
| 12 | 操作         | 不变                 | —（单行居中）。最多外露 5 个操作图标，超出时第 5 个变为「...」收纳剩余操作。hover 图标时 Tooltip 显示操作名称 |

**操作列详细规则：**

操作列表头显示 "操作" 文字（14px，`semantic.text.placeholder`，medium 字重）。

默认外露 5 个操作图标（来自 Figma，从左到右），每个 16×16px，间距 16px：

| 图标                     | 操作名称  |
| ------------------------ | --------- |
| View-list（详情列表）    | 详情      |
| 日志图标                 | 日志      |
| Hammer-and-anvil（铁锤） | 删除/重建 |
| 屏蔽图标                 | 屏蔽      |
| More（⋮）                | 更多      |

**超出 5 个操作的规则：**

- 若 Pod 的可用操作超过 5 个，前 4 个按原有顺序外露，第 5 个固定为「...」（More 图标）
- 点击「...」弹出 Dropdown，展示剩余操作项
- hover 任意操作图标时，显示该操作的名称（Tooltip）
- 操作图标及顺序由 Pod 的 `operations` 字段决定，`disabled=true` 时该项置灰

**列补充说明：**

- 第 2 列（Pod 名称）：列表头左侧有快捷批量选择小箭头，hover 旋转向上弹出 Dropdown。内容区域支持复制 Pod 名称：复制按钮默认隐藏，鼠标悬停到 Pod 名称内容区域时显示，点击复制到剪贴板
- 第 5 列（端口）：数据来源 `containers[].ports[]`，显示格式 `name:port`。端口数量超出显示区域时末尾显示 `+N`（如 `grpc:8500 +1`），`+N` 文字颜色 `semantic.text.placeholder`。name 部分 `semantic.text.secondary`，port 部分 `semantic.text.primary`，均使用 Menlo 字体。`ContainerPort` 实体已含 `name/port/protocol`，直接取用；若某端口 `name` 为空则仅展示 `port`
- 第 4 列（Pod IP / 节点 IP）：Pod IP 和节点 IP 各自支持复制操作。各自的复制按钮默认隐藏，鼠标悬停到对应内容区域时显示，点击复制到剪贴板
- 第 6 列（服务暴露）：**当前接口未返回对应字段**，暂用占位展示，后续接入
- 第 3 列（状态）：详细模式扩展行显示 `readyContainers` / `totalContainers`，格式为"就绪容器数/总容器数"
- 第 7 列（重启）：字段映射 `restarts`，显示重启次数。颜色编码：≥6 红色（`error-6`），3-5 橙色（`warning-6`），≤2 黑色（`semantic.text.primary`），使用 Menlo 字体右对齐。hover 数值时 Tooltip 展示 `lastStartedAt`（上次启动时间）
- 第 8 列（存活）：前端根据 `creationTimestamp` 与当前时间计算差值展示（如"3d 5h"），使用 dayjs
- 第 9、10 列（CPU / 内存）：详细模式扩展行显示图标 + 使用率百分比，高负载红色（`error-6`），正常黑色（`semantic.text.primary`）。精简模式仅显示百分比数字
- 第 11 列（GPU）：独立列，无 GPU 时整列隐藏

**交互规则：**

- 默认全部展开、详细模式
- 收起状态下，表格行隐藏（只保留组标题行可见）
- 每个 group 表格独立分页，翻页不影响其他 group
- GPU 列：如果整个工作负载组没有 GPU 资源，则隐藏该列
- 详细模式下扩展行为空的列（☑ / 重启 / 存活 / 操作），单行内容垂直居中
- 列顺序：Pod 名称列固定在左侧；滚动时表头字段随滚动吸顶
- 支持列排序：重启次数、存活、状态（共 3 列，其他列暂不支持）

### 4. 批量操作栏（BatchActionBar）

保留现有 `BatchActionBar` 壳子和显隐机制不变。PodContentArea 选中 Pod 后通过 `createPortal` 将批量操作内容渲染到页面级 portal 目标容器。选中数量**跨 group 累计**（如 group A 选中 2 个 + group B 选中 1 个 = 显示"已选择 3 个实例"）。

### 5. 状态处理

| 状态       | 行为                                 |
| ---------- | ------------------------------------ |
| 加载中     | 表格内显示 Spin loading              |
| 空数据     | 显示 antd Empty（"暂无 Pod"）        |
| 筛选无结果 | 显示 Empty（"未找到符合条件的 Pod"） |
| 错误       | 显示错误提示 + 重试按钮              |
| 权限拒绝   | 显示 Empty + 权限提示文案            |

## Main User Flows

### 查看 Pod 列表

```
用户进入工作负载页面
  → 看到概览卡片（已有）和 Pod 列表内容区（按组展示，默认全展开、详细模式）
  → 每个 group 独立分页（默认 10 条/页），底部有独立分页器
```

### 快捷筛选

```
用户看到筛选区右侧的快捷筛选按钮组（全部 54 / 正常 24 / 异常 12 / 已屏蔽 2）
用户点击"异常"
  → 快捷筛选"异常"按钮变为选中态（深色文字 + medium 字重）
  → 左侧「Pod 状态」Select 自动设置为"异常"对应的状态值
  → 所有 group 表格仅展示异常状态的 Pod
  → 分页重置到第 1 页
```

### 手动筛选覆盖快捷筛选

用户手动修改「Pod 状态」Select，加选"异常"

## Business Rules

1. 筛选条件 AND 逻辑：状态、屏蔽与解除屏蔽、搜索三个条件同时生效
2. 搜索范围：Pod 名称 + Pod IP，不区分大小写模糊匹配
3. 快捷筛选与 Pod 状态 Select 双向联动：
   - 选快捷筛选 → 自动设置 Pod 状态 Select 的值
   - 手动改 Pod 状态 Select → 取消快捷筛选的选中态
   - 快捷筛选始终单选，Pod 状态 Select 为多选
4. 详细/精简模式切换对全局生效，切换后不重置筛选和分页
5. 收起/展开对全局生效
6. GPU 列按组级判断是否显示：如果该组内所有 Pod 均无 GPU 资源，隐藏 GPU 列
7. 批量操作栏仅在至少选中 1 个 Pod 时浮现

### Pod 状态展示规则

**状态列渲染**（来源：API 文档 Pod 状态整理表）：

- 优先查找状态表匹配中文名展示（如 `Running Ready` → "运行中"）
- 未匹配到的状态直接展示原始 `status` 字段值
- 鼠标悬浮（Tooltip）时展示 `status` 原始内容

**状态徽章颜色**（依据状态表中"颜色"列）：

| 颜色 | 适用状态                                                                                                                   | token                            |
| ---- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 绿   | Running Ready、Completed                                                                                                   | `semantic.state.success.default` |
| 蓝   | Terminating、Pending、ContainerCreating、PodInitializing、Init:xxx                                                         | `semantic.state.info.default`    |
| 黄   | Running InPlaceUpdateNotReady、Running NotReady                                                                            | `semantic.state.warning.default` |
| 红   | CrashLoopBackOff 及 Init 变体、CreateContainerError、ImagePullBackOff、OOMKilled、Evicted 等所有"是否正常=否"且非黄/蓝状态 | `semantic.state.error.default`   |

**状态筛选下拉**：选项来源于 Pod 列表接口 `summary.statuses[]`，显示格式为 `中文名（count）`，如 `运行中（6）`。

### 快捷筛选数据来源

计数数据来源于 Pod 列表接口的 `summary` 字段（`PodStatistics` 结构）：

| 按钮   | 计数来源                                                                                      | 筛选动作                                       |
| ------ | --------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 全部   | `summary.totalCount`                                                                          | 清除 Pod 状态 Select 选中值，`status` 参数不传 |
| 正常   | Running Ready + Completed + Terminating + Running InPlaceUpdateNotReady 四种状态的 count 之和 | 设置 Pod 状态 Select 为这四种状态的筛选值      |
| 异常   | `totalCount` - 正常计数                                                                       | 设置 Pod 状态 Select 为"是否正常=否"的全部状态 |
| 已屏蔽 | `summary.blockedCount`                                                                        | 设置 `blocked=true`                            |

## Roles / Permissions

- 不做页面级权限控制（ 依赖已有 APISIX 路由级鉴权）
  - 操作可见性由后端返回的 `operations` 字段控制，`disabled` 为 `true` 时对应图标置灰
  - **批量操作按钮置灰规则**：已选中的 Pod 列表中，若任一 Pod 的某项操作 `disabled=true`，则对应的批量操作按钮置灰（不可点击）

## Edge Cases

| 场景                    | 处理                                              |
| ----------------------- | ------------------------------------------------- |
| 所有 group 均无 Pod     | 显示 Empty（"暂无工作负载实例"）                  |
| 某 group 无 Pod         | 该 group 区域显示组标题 + Empty（"该组暂无 Pod"） |
| 筛选后某 group 为空     | 该 group 区域正常显示组标题 + Empty               |
| 搜索无匹配              | 所有 group 显示 Empty（"未找到符合条件的 Pod"）   |
| 数据加载失败            | 显示错误提示 + 重试按钮                           |
| 多个 group 同时存在     | 按 group 顺序垂直排列，各 group 独立滚动其表格    |
| 分页切换时收起/展开状态 | 分页不影响展开/收起状态                           |
| 快捷筛选与 Select 同步  | 快捷筛选是 Select 的快捷入口，两者值同步即可      |
