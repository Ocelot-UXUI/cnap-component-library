CNAP2.0 应用-应用列表 / 应用模板 / 应用设置

原型：[https://cnap-2.now.baidu-int.com/devops/cnap/applications](https://cnap-2.now.baidu-int.com/devops/cnap/applications)

## 1. 文档信息
* 文档范围：CNAP 2.0 中「应用列表」「应用模板」「应用设置」三个模块的产品需求。
* 相关入口：
    * 应用列表 `/applications`
    * 应用模板列表 `/application-templates`
    * 应用模板详情 `/application-templates/{templateId}`
    * 应用设置 `/application-settings`


## 2. 背景与目标
CNAP 2.0 将「应用」作为平台的一等实体。用户需要一个统一入口来发现和进入自己关心的应用，需要可复用的配置载体来降低新建应用的成本，也需要一个集中位置管理单个应用的元信息、成员与生命周期。

三个模块分别承担：

* **应用列表**：应用的发现与导航中心。解决「我有哪些应用、哪个出了问题、从哪里进去」。
* **应用模板**：标准化配置的沉淀与复用中心。解决「新建应用时不用从零填参数、团队之间共享最佳实践」。
* **应用设置**：单应用的治理中心。解决「谁能改这个应用、它从哪来、怎么下线」。

目标：

1. 应用列表在一屏内暴露健康状态、环境、最近生产变更，用户无需进入详情即可判断是否需要处理。
2. 模板可从既有应用一键沉淀，并支持跨账户共享与复制，形成配置资产。
3. 应用设置的所有写操作受统一权限模型约束，高风险操作强制二次确认。

## 3. 范围说明
### 3.1 本期范围
* 应用列表的筛选、排序、置顶、卡片/表格双视图、行级操作。
* 应用模板的列表（全部模板 / 我创建的）、复制、共享、删除、以模板新建应用、模板详情页基本信息与版本。
* 应用设置的基本信息、成员管理、高级配置三个 Tab。
* 三个模块之间的跳转联动。

### 3.2 不在本期范围
* 模板详情页的 运行配置 / 部署策略 / 构建 / 插件 / 首次部署 五个 Tab 的实质内容，仅保留 Tab 占位。

## 4. 术语与规则
### 4.1 应用类型
平台固定四类，两个模块的枚举需保持语义一致：

* 云原生微服务应用
* 轻量级后端应用
* AI 模型推理应用
* Agent 沙箱应用

### 4.2 环境
环境是应用与工作负载之间的必经维度：从应用列表点击某个环境即进入该环境的工作负载页。

### 4.3 创建来源
* 模板创建：展示「基于「X」模板创建」，模板名可点击跳转模板详情；来源模板已删除时，不可点击跳转模板详情，追加「（模板已删除）」提示。
* 空白创建：展示「空白创建」。

创建来源创建后不可修改。

### 4.4 模板可见性与能力
* 模板归属账户 + 归属用户。
* 本账户模板账户级可见，是否可编辑由权限点决定。角色派生为3档：模板负责人/模板创建人（模板创建人默认成为该模板的模板负责人） 可以编辑模板，账户其他成员仅有模板只读权限。
* 跨账户引用的模板**内容只读**：可使用、可复制，不可编辑、不可再共享；有模板管理权限者可将其从本账户移除，该操作不影响来源账户的原始模板。
* 能力集合为  复制  / 共享 / 删除 3项，操作菜单按能力动态过滤，卡片视图与表格视图共用同一套能力判定。

### 4.5 时间与文案约定
* 时间统一 `YYYY-MM-DD HH:mm:ss` 展示。
* 空值统一展示 `—`。
* 成员相关的写操作成功提示统一追加「，已通过如流人人卡通知相关用户」。

## 5. 应用列表需求
### 5.1 页面定位
`/applications`，页头标题「应用列表」，右侧提供两个主操作：

* 创建应用：打开创建应用弹窗，在当前页完成创建。
* 从模板创建：跳转 `/application-templates`，由模板列表承载选型过程。

### 5.2 列表字段
每条应用记录包含以下信息：

* 标识与展示：应用名称、描述、应用图标。
* 分类：应用类型标签、平台生成的属性标签（如 定时任务 / SidecarSet 应用 / 有状态应用）、用户自定义标签。
* 环境：部署环境列表。
* 变更：最近更新人、最近更新时间、最近生产变更（变更人 / 变更时间 / 环境名 / 变更类型，四段以 `·` 拼接展示，无变更展示 `—`）。
* 使用痕迹：最近使用时间、是否收藏。

平台生成的属性标签由平台生成，用户不可编辑；自定义标签可编辑/修改/删除（编辑入口在应用设置，也可以在账户-标签管理进行管理）。

### 5.3 筛选
筛选条件四项，**条件之间取交集，同一条件内多选取并集**：

* 关键词：匹配应用名称或描述，忽略大小写。
* 应用类型：多选。
* 环境：多选。
* 标签：多选。

筛选后无结果时展示「没有符合筛选条件的应用」；账户下本身无应用时展示「暂无应用」。两种空态必须区分，避免用户误判为数据丢失。

### 5.4 排序与置顶
列表排序为固定策略，用户不可自定义。分组优先级：

1. 当前应用（用户当前正在操作的应用，始终位于首位，应用标识能看出来有「当前」标记）
2. 已收藏应用
3. 有最近使用记录的应用
4. 其余应用

同一分组内按最近使用时间倒序。收藏与取消收藏即时影响排序。

### 5.5 双视图
* 表格视图列顺序与宽度：名称（左侧固定）| 类型 | 属性 | 描述 | 环境 | 标签 | 最近生产变更 | 操作（右侧固定）。属性、描述、标签、最近生产变更为空时展示 `—`。
* 视图切换状态在工具栏维护，切换不影响筛选条件。

### 5.6 行内交互
所有跳转类交互都会**先把该应用切换为当前应用上下文**，再进入目标页面，保证目标页读到的是正确的应用。

* 点击应用名称：切换上下文并进入该应用的工作负载页，入口环境按下述规则解析。
* 点击环境标签：切换上下文与环境，进入工作负载页。入口环境的选择规则为：若用户当前所处环境仍属于该应用则沿用，否则优先 `prod`，再否则取该应用排序后的第一个环境。
* 点击最近生产变更：切换上下文并跳转该应用的部署管理页。
* 操作列提供：应用设置（跳转应用设置页，默认基本信息 Tab）、收藏 / 取消收藏、另存为应用模板。
* 「另存为应用模板」复用模板表单弹窗，以当前应用配置预填，提交后写入模板列表。

## 6. 应用模板需求
### 6.1 页面定位
`/application-templates`，与应用列表平级的独立页面，侧边栏底部区域提供入口。页头由标题「应用模板」与 Tab 组成同一行。

### 6.2 Tab 分类
当前实现两个 Tab：

* 全部模板：本账户可见的全部模板，含跨账户引用进来的模板。
* 我创建的：等于当前用户的模板。

Tab 支持通过路由 state 指定初始值，便于从其他页面跳转时直接落在「我创建的」。

空态文案按 Tab 区分：

* 全部模板：「暂无模板，可在应用列表中通过「另存为应用模板」沉淀标准化配置」——空态本身承担引导职责。
* 我创建的：「你还没有创建模板」。
* 筛选后无结果：「没有符合筛选条件的模板」。

### 6.3 列表字段
* 标识：模板 ID、模板名称、模板图标、描述。
* 分类：应用类型标签、属性标签。
* 归属：归属账户、归属用户、引用来源（跨账户引用时记录来源账户 ID 与名称）。
* 变更：最近更新人、最近更新时间。
* 共享配置：被共享到的账户列表。

### 6.4 筛选与排序
* 筛选两项：关键词（匹配模板名称或描述）、应用类型（多选，选项从当前模板集合动态派生）。
* 排序固定为最近更新时间倒序，不提供用户可选排序项。

### 6.5 视图
卡片视图与表格视图双形态，默认卡片视图。

### 6.6 复制模板
* 入口：操作菜单「复制模板」，对所有可见模板开放（含跨账户引用的只读模板）。
* 确认提示：「复制会生成一个归属于你的新模板。确认后可在下一步修改基本信息，再完成创建。」
* 复制生成的新模板归属当前用户，与来源模板相互独立，来源模板的后续修改不同步到副本。
* 复制弹窗标题为「复制模板「X」」，隐藏复制来源选择项（来源已确定）。

### 6.7 共享模板
* 该账户所有人 可见「共享模板」入口；跨账户引用的模板不可再共享。
* 共享维度为账户级：选择目标账户后，该账户成员可见并可使用该模板，但内容只读。
* 共享是引用而非拷贝：来源账户修改模板，被共享账户看到的是最新内容。

### 6.8 删除模板
按模板归属区分文案与影响范围：

* 本账户模板，菜单项「删除」（危险态）：「删除后已基于该模板创建的应用不受影响，但无法再基于此模板新建应用。」
* 跨账户引用的模板，菜单项「从本账户删除」：「仅从本账户移除该模板，不会删除账号「X」下的原始模板。删除后本账户无法再基于此模板新建应用，已创建的应用不受影响。」

### 6.9 模板详情页
`/application-templates/{templateId}`，七个 Tab：基本信息（默认）/ 运行配置 / 部署策略 / 构建 / 插件 / 首次部署 / 版本。其中仅基本信息与版本有实质内容，其余为占位。

版本记录为追加式，不可编辑历史：

* 版本号、变更类型（首次发布  / 更新  / 回滚 ）、发布时间、操作人、自定义更新说明。
* 每个版本保存完整内容快照（类型、图标、描述、共享配置、应用配置）。查看历史版本即读取该快照，**不会**把当前模板还原到该版本。

## 7. 应用设置需求
### 7.1 页面定位
`/application-settings`，三个 Tab：基本信息（默认）/ 成员管理 / 高级配置。

全局约束：

* 应用名称创建后**永久只读**，任何角色不可修改。
* 原始应用标签**仅账户负责人**可删除/修改，应用负责人可以对本应用的标签进行增删改。非账户负责人/应用负责人 看到的标签区为不可编辑的只读状态。
* 风险操作强制二次确认。

### 7.2 基本信息
展示与编辑区块：

* 应用图标：可编辑区块，支持系统内置/用户上传/ AI 生成。
* 应用描述：应用负责人 可编辑，保存后提示「已保存」。
* 只读信息四项：应用类型、创建人 · 创建时间、最近变更、创建来源。
    * 最近变更点击可跳转该应用的部署管理页。
    * 创建来源为模板继承时，模板名可点击跳转模板详情页；模板已删除时展示「（模板已删除）」且不可跳转。

* 应用标签：独立区块。

### 7.3 成员管理
* 表格列：成员 | 绑定角色 | 最近活跃 | 操作。
* 成员类型分个人与邮件组。
* 角色：从账户那儿共享角色。
* 排序：应用负责人恒定置顶，其余保持原有顺序。
* 搜索：匹配用户名或邮箱，忽略大小写。
* 添加成员：应用负责人 才展示「添加成员」按钮。支持一次输入多个邮件地址（换行或英文逗号分隔）。
    * 全部地址已是成员时提示「填写的邮件地址均已是应用成员」（警告态，不写入）。
    * 部分新增时提示「已添加 N 位成员，角色即时生效，已通过如流人人卡通知相关用户」。

* 修改角色：以增量方式提示「{用户名} 新增角色：X；移除角色：Y，已通过如流人人卡通知相关用户」。
* 移除成员：二次确认后提示「已移除成员「X」，其已失去应用访问权限，已通过如流人人卡通知相关用户」。**应用至少保留一位成员**，成员数为 1 时删除按钮禁用。
* 空态：「暂无应用成员，点击右上角添加成员进行授权」。

### 7.4 高级配置
两个分区，操作按钮在无 应用负责人 权限时禁用。

**应用模板分区**（标题「应用模板」，说明「将当前应用的配置沉淀为可复用的应用模板。」）

* 操作：另存为应用模板。
* 说明：「仅通过复制当前应用配置生成全新模板，应用与模板相互独立；后续应用的配置修改不会同步至模板。」
* 复用模板表单弹窗的简化模式，标题「另存为应用模板」。

**生命周期操作分区**（说明「高风险操作，请确认影响范围后再执行。」）

* 操作：删除应用（危险区样式）。说明「销毁所有运行副本，数据不可恢复，需先处理关联事项并二次确认。」
* 删除流程为**双层确认**：

    1. 第一层弹窗（标题「删除应用」）：顶部错误级警告「删除应用将删除研发流程、编排、变量组、环境、部署单、版本等数据，解除与流水线的关联关系，且不可恢复，请谨慎操作」；列出关联事项清单（迁移监控告警 / 清理日志存储 / 更新服务依赖关系 / 备份生产数据 / 通知团队成员），必须**逐项勾选全部**；再要求手动输入应用名称，应用名 token 禁止复制、输入框禁止粘贴，输入框占位「请手动输入应用名称」。
    2. 全部勾选且名称完全一致时「确认删除」才可点击，点击后弹出第二层确认，内容「应用「X」及其所有相关关联关系将被永久销毁，操作不可恢复。确认删除？」
    3. 确认后提示「应用已删除」。

## 8. 模块间联动
* 应用列表 →「基于模板创建应用」→ 模板列表页面：模板列表承担选型，选定后回到创建应用弹窗。
* 应用列表 →「另存为应用模板」→ 模板列表-我创建的页面：新模板即时出现在列表首位，归属当前用户。
* 模板列表 / 模板卡片 →「以此模板新建应用」→ 创建应用弹窗（模板字段锁定）→ 创建成功后回到应用侧。
* 应用列表 → 操作列「应用设置」→ 应用设置页。
* 应用列表 / 应用设置 →「最近生产变更」→ 该最近变更的部署单详情页。
* 应用设置 → 基本信息「创建来源」→ 模板详情页（模板未删除时）。
* 应用设置 → 高级配置「另存为应用模板」→ 模板列表新增模板，进入应用模板-我创建的 页面。
* 应用列表 → 环境标签 → 该应用在该环境下的工作负载页。
* 应用列表 → 应用名称 / 卡片空白处 → 该应用在prod环境下的工作负载页（如果没有prod就进入其他环境页面）。
