# 2026-07-23

## 更新 — 工作负载需求文档调整

基于 API 文档 `docs/input/source-api-runtime-workloads.md`（Restart / HorizontalScale / VerticalScale 操作说明），对工作负载模块的需求文档做了以下调整：

### app-restart-modal.md — 重写为"重启弹窗"

- 改名为"重启"（原"应用重启"，对应 API `capability: Restart`）
- 新增工作负载（Group）选择步骤：用户先选 Group → 调用 `runtime/workloads?groupId=xxx` 获取 Workload 列表
- 集群表格数据来源从「查询集群列表」改为「查询 Workload 列表」
- 容器选择：用户勾选集群后系统自动默认选中该 Workload 的第一个容器
- 集群表格列字段映射更新：
  - 最大不可用 → `updateStrategy.maxUnavailable`（可编辑）
  - 最大可超出 → `updateStrategy.maxSurge`（新增列，只读）
  - 可用度 → `availabilityTarget`（为空时显示"未启用"）
- 补充了 trigger 接口格式与请求体示例
- 补充了与批量重启 Pod（PodRestart）的差异对比

### pod-list-content-area.md — Group 更多按钮调整

- 「工作负载 YAML」按钮仅在选择集群后才可触发（cluster + group 才能唯一确定 Workload）
- 该按钮由前端自行拼接到操作列表中（不在后端 `operations` 字段）
- 操作列表拼接规则：后端 `operations` 在前，前端拼接「工作负载 YAML」在末尾

### horizontal-scale-dialog.md — 新增 Group 选择步骤

- 与重启弹窗模式一致：先选 Group → 调用 `runtime/workloads` → 选择 Workload
- 表格数据改为来源于 Workload 列表接口
- 补充了 trigger 接口格式与请求体示例
- 补充了依赖接口清单

### vertical-scale-dialog.md — 新增 Group 选择 + 容器选择步骤

- 与重启弹窗模式一致：先选 Group → 选 Workload → 选容器
- 容器选择：系统默认选中第一个容器，用户可手动切换
- 补充了 trigger 接口格式与请求体示例
- 补充了与重启弹窗的差异对比

### 关联更新

- `workloads-page.md`：外露按钮"应用重启" → "重启"
- `batch-restart-pod-modal.md`：关联引用"应用重启弹窗" → "重启弹窗"
- `docs/requirements/README.md`：索引条目"应用重启弹窗" → "重启弹窗"

### app-restart-modal.md — 容器选择交互细化 + 数据来源基线

- 容器选择改为**手动选择**（不再自动强制第一个容器）：
  - 新增弹窗级容器选择器（位于 Group 选择器下方），与 Group 选择器联动
  - 集群表格每行新增独立的"容器"列（下拉框），默认值由弹窗级容器选择器联动控制
  - 切换弹窗级容器选择器 → 所有已勾选行的容器值同步更新；未勾选行保持原值
  - 切换行级容器下拉框 → 仅当前行生效，独立于弹窗级选择器
- 新增「数据来源基线」表格，逐列注明接口与字段映射：
  - Checkbox → 前端状态
  - 集群 → `runtime/workloads` / `clusterName`
  - 容器 → `runtime/workloads` / `containers[].name`（当前行）
  - 最大不可用 → `runtime/workloads` / `updateStrategy.maxUnavailable`
  - 最大可超出 → `runtime/workloads` / `updateStrategy.maxSurge`
  - 可用度 → `runtime/workloads` / `availabilityTarget`
- 更新交互逻辑表，补充容器选择相关操作

### app-restart-modal.md + vertical-scale-dialog.md — 容器选择器位置调整

- 容器选择器从集群表格中移出，改为与工作负载（Group）选择器**相邻放置**
- 重启弹窗和纵向扩缩弹窗统一采用此布局：
  - 顶部：工作负载（Group）Select + 容器 Select（相邻）
  - 下方：集群表格（不含容器列）
- 容器选择器数据来源：聚合 Group 下所有 Workload 的 `containers[].name`，去重后填充
- 提交时 `targets[].container` 统一取弹窗级容器选择器的值
- 纵向扩缩弹窗同步移除了表格中的容器列

### 弹窗需求文档审查 — API/字段补充 + 校验规则

基于源码 `src/api/runtimeOperation.ts` 审查结果：

- **trigger 接口引用统一**：所有弹窗的触发接口从裸 URL 改为引用 `runtimeOperationApi` 封装方法：
  - `app-restart-modal.md` → `runtimeOperationApi.restartWorkload()`
  - `horizontal-scale-dialog.md` → `runtimeOperationApi.horizontalScale()`
  - `vertical-scale-dialog.md` → `runtimeOperationApi.verticalScale()`
  - `batch-restart-pod-modal.md` → `runtimeOperationApi.restartPod()`
  - `batch-pod-delete-rebuild-dialog.md` → `runtimeOperationApi.deletePod()`
  - `delete-deployment-resource-dialog.md` → `runtimeOperationApi.triggerOperation()`
- **补充 request body 字段来源映射表**：restart/horizontal-scale/vertical-scale 三文档新增 `targets[].clusterId` / `resourceType` / `name` 等字段的来源说明
- **新增数据来源基线表**：`horizontal-scale-dialog.md` 和 `vertical-scale-dialog.md` 补充了接口→字段映射表；`batch-restart-pod-modal.md` 补充了 Pod 预览表格和集群参数配置表的数据来源；`batch-pod-delete-rebuild-dialog.md` 补充了数据来源章节；`delete-deployment-resource-dialog.md` 补全了集群列表接口路径和字段
- **CPU/内存默认值来源**：`vertical-scale-dialog.md` 标注了输入框初始化值从 `containers[].resourceLimits/resourceRequests` 预填
- **校验规则细化**：
  - 最大不可用：0%~100% → **1%~100%**（restart / batch-restart-pod）
  - 超时时间：>=1秒 → **5~3600秒**（restart / batch-restart-pod）
  - CPU/内存单位：CPU → `c`/`nc`；内存和临时存储 → `Mi`/`Gi`/`Ti`（vertical-scale）
  - 纵向扩缩新增校验：Limit 值不能小于同资源 Req 值
- **跨文档命名统一**："可用度锁" → "可用度"（batch-restart-pod、batch-pod-delete-rebuild）
- **过期描述修正**：horizontal-scale 对比表中重启容器选择描述同步更新；副标题"重启应用" → "重启操作"
