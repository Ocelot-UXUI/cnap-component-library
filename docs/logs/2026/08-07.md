## 操作弹窗集群表格筛选列统一为 rowSelection（verticalScale / horizontalScale / restart）

- 背景：三个操作弹窗（纵向扩缩 / 横向扩缩 / 重启）的 `ClusterTable` 复制了同款手写 Checkbox 筛选列（`title: ''` + `key: 'select'` + `width: 40` + `<Checkbox checked={row.selected} />`），无表头全选、无批量操作，与 `PodGroupTable` 的 antd 原生 `rowSelection` 写法不一致。
- 方案（评审确认）：rowSelection 仅作受控视图，选中真源仍是 machine context 的 `row.selected`（联动副作用：纵向扩缩 Lim 镜像/回滚、重启 maxUnavailable 回滚、行内输入 disabled、canSubmit/toTargets 过滤都依赖它）。`selectedRowKeys` 从 rows 单向派生；`onChange` 对新旧选中键求差集、逐 key 派发原 `TOGGLE_CLUSTER`，保持领域逻辑与测试零改动。同时保留 antd 默认表头全选与选中行高亮，并配置 `selections: [SELECTION_ALL, SELECTION_INVERT, SELECTION_NONE]` 全选/反选/全不选下拉（与 PodGroupTable 一致）。`columnWidth: 40` 对齐原列宽。
- 变更：
  - Add `src/pages/Workloads/operations/shared/selection.ts`（共享纯函数 `toggledKeys`，参数兼容 antd 的 `Key[]` 含 bigint）+ `__tests__/selection.test.ts`（5 用例）。
  - Mod 三个 `ClusterTable.tsx`：删除手写 select 列与 `Checkbox` import，Table 增加受控 `rowSelection`；移除列后各文件保持 <150 行。
- 验证：`yarn lint-type` PASS；`yarn lint` 与基线一致（仅既有 `src/utils/i18n/index.ts` 2 处 no-explicit-any error 与既有 max-lines warning，本次改动的 5 个文件无 lint 问题）；`yarn test` 31 文件通过，6 个失败文件为既有失败（ResizeObserver 未定义 / 401 网络，与 08-06 基线一致），新增 `selection.test.ts` 单独运行 PASS。

## 横向扩缩：期望副本数编辑自动选中 + 取消选中回滚初始值

- 需求：横向扩缩表格中修改某行「期望副本数」时该行自动选中；取消选中时该值重置为最初值。与 restart 弹窗既有模式（`editMaxUnavailable` 自动选中 + `toggleCluster` 回滚 `originalMaxUnavailable`）对齐。
- 实现（`horizontalScale/rows.ts`）：`editDesired` 改为 `selected: true`（修改未选中集群时自动选中）；`toggleCluster` 取消选中时 `desired` 回滚为 `String(row.replicas)`——`buildRows` 中初始 `desired` 即 `String(w.replicas)`，且 `replicas` 为只读当前副本数，无需新增 original 字段。`rowSelection` 受控派生自 `row.selected`，自动选中/回滚会实时同步到复选框。
- 变更：Mod `horizontalScale/rows.ts`（2 个纯函数 + 注释）；Mod `horizontalScale/__tests__/rows.test.ts` 追加 5 个用例（editDesired 自动选中、toggleCluster 选中保持/取消回滚/再选中保持回滚值）。
- 验证：`yarn lint-type` PASS；`yarn vitest run horizontalScale/__tests__/rows.test.ts` PASS（既有 7 用例 + 新增 5 用例）；`yarn test` 全量对比仍为 6 个既有失败文件，无新增回归。

## 纵向扩缩：表单项校验错误信息内联展示

- 需求：纵向扩缩表单项有自己的校验规则，校验失败需把错误信息显示给用户；覆盖"Req 空 + Lim 勾选"盲区；仅纵向；即时校验。
- 校验层（`verticalScale/rows.ts`）：`isPairValid` 布尔判定重构为导出 `validatePair(kind, pair): { side: 'req' | 'lim'; message: string } | null`，按优先级返回首个错误文案（勾选限制前请先填写请求值 / 请求值需为大于 0 的数值 / 限制值需为大于 0 的数值 / 限制值不能小于请求值）；Req 空且 Lim 未勾选仍视为未配置跳过。`isPairValid` 改为 `validatePair(...) === null`。
- 联动修复（`toggleCluster`）：原实现选中时无条件为所有 kind 启用 Lim 并镜像 Req，导致接口未返回的资源项（req.value===''）也被勾选 Lim，触发新校验。改为未配置资源项不参与 Lim 联动。
- 展示层（`ResourceCell.tsx`）：Req/Lim 各行下内联 `FieldError`（`semantic.state.error.default` + `typography.caption.regular`），对应 InputNumber/Select 走 `status="error"`；提取 `errorStatus`/`limDisabled` 控制圈复杂度（lint 上限 10）。保留用户自行升级的 InputNumber（`min='0'`、清空 `value ?? ''`）。
- 底部提示（`selectors.ts`）：`selectBottomHint` 区分"未选中集群"与"选中行校验未通过"两类文案，修复原固定文案误导。
- 测试：用户已建 `verticalScale/__tests__/rows.test.ts`（10 用例），追加 `validatePair` 7 用例。
- 验证：`yarn lint-type` PASS；`yarn vitest run verticalScale/__tests__/rows.test.ts` PASS（17 用例）；`yarn lint` 与基线一致（仅既有 i18n 2 error + 既有 max-lines warning，`rows.ts` 因新增校验函数 145→160 行 warning 增量，无 error）；`yarn test` 全量仍为 6 个既有失败文件，无新增回归。
