## API 基建：迁移到 axios-interface

**背景**: 按 `API_BUILDING_MIGRATION_GUIDE.md` 建立 AppSpace 主服务请求工厂，废弃 `src/api/base.ts`。当前项目尚未接入真实后端接口，本轮仅建设底座；不迁移现有业务 API 与类型，不引入测试。

**变更内容**:

- 新增依赖 `axios-interface@2.1.1`、`qs@6.15.3`、`@types/qs@6.15.1`
- 新增 `src/api/services/primary/`：
  - `paramsSerializer.ts` — `qs.stringify`（`arrayFormat: 'comma'` / `skipNulls` / `allowDots`）
  - `commonOptions.ts` — 空 `headers` + `withCredentials: true`
  - `index.ts` — `createFactory({baseURL:'/api/appspace', ...getCommonOptions(), paramsSerializer, onResolve, onReject, enhance})`，导出 `createInterface` / `request`
- `onResolve` 只返回 `response.data`；`onReject` 调用 `tryConfirmSessionLost` 后 `throw error`
- `enhance` 提供接口级 mock：`createInterface(method, url, {mock: data})` 在 `APP_IS_DEV` 下短路请求，直接 `Promise.resolve(mock)`
- 删除 `src/api/base.ts`（旧 `axiosInstance` / `X-Trace-ID` / 业务 code 判定全部丢弃）
- 新增 `docs/architecture/api-infrastructure.md`；更新 `docs/context/codebase-map.md` 中 API 层条目

**修改文件**:

- `package.json`、`yarn.lock` — 新增三项依赖
- `src/api/services/primary/paramsSerializer.ts`（新建）
- `src/api/services/primary/commonOptions.ts`（新建）
- `src/api/services/primary/index.ts`（新建）
- `src/api/base.ts`（删除）

## Mock 数据迁移至 API 接口配置

**背景**: 将导航上下文的 mock 数据（account/application/environment）和工作负载的操作按钮 mock 数据迁移至 `src/api/` 对应接口的 `{mock}` 配置上；消费侧类型从旧 mock 类型迁移到 API 实体类型。

**变更内容**:

- 扩展 `enhance` mock 机制：支持 `mock: (params) => value` 函数形式，使 param 感知 mock 可行
- `src/api/account.ts` — `getMany` / `getApplicationsByAccount` 传入 `{mock}` 参数，mock 数据使用 `Account[]` / `Application[]`（number ID）
- `src/api/applicationEnvironment.ts` — `getEnvironments` 传入 `{mock}` 参数，mock 数据使用 `AppEnvironment[]`
- `src/api/runtimeOperation.ts` — `getOperations` 传入 `{mock}` 参数，mock 数据使用 `RuntimeOperation[]`
- `NavigationContextState` ID 从 `string` 改为 `number`；`NavigationContextCandidates` 使用 `Account` / `Application` / `AppEnvironment`
- `loadNavigationContextCandidates` 改调 `accountApi.getMany` / `accountApi.getApplicationsByAccount` / `applicationEnvironmentApi.getEnvironments`
- `getSnapshot` 的 `availableEnvironments` 过滤从 `accountId + applicationId` 改为仅 `applicationId`
- localStorage 读取增加类型校验，不符合 number 类型时清空缓存
- `navigationOptionGroupMachine` 改调真实 API + builder 函数（不再走旧 wrapper 函数）
- `staticData.ts` 重命名为 `selectorBuilders.ts`，删除 mock 数据，保留 builder 函数（builder 参数类型改为 `Account` / `Application` / `AppEnvironment`）
- `navigationContext/index.ts` 删除全部 6 个旧函数，仅 re-export 类型
- `navigationContext/mockData.ts` 删除（废弃副本）
- `WorkloadsHeader` 从 `getOperations` 获取 `RuntimeOperation[]` 并直接渲染；`danger` 通过 `OperationCapability` 识别
- `HeaderAction` 类型删除；`primaryActions` / `moreActions` 从 `Workloads/mockData.ts` 删除
- `ApplicationsPage` 改调 `accountApi.getApplicationsByAccount`，类型从 `ApplicationOption` 改为 `Application`
- 测试文件更新 ID 值从 string 改为 number

**验证**: `yarn lint-type` 通过；`yarn build` 通过；`yarn test` 通过（1 个 pre-existing 失败非本次引入）。
