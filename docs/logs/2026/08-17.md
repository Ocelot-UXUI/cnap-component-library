## Mock 装配方式修正：接口处内联 `{mock: ...}`（用户指正）

用户指出 mock 应直接写在 `createInterface` 调用处的 options 上（先例：`account.getMany` 的 `{mock: MOCK_ACCOUNTS}`），弃用此前「mock 模块预装配 options + URL `?mock=workloads` 开关」的间接写法。

- 范式：静态数据直接传值（`{mock: MOCK_ACCOUNTS}` / `{mock: MOCK_GROUPS}` / `{mock: MOCK_OPERATIONS}`），参数相关接口传 builder 函数（`{mock: buildMockPodList}` 等，enhance 自动以 params 调用）。
- 变更：删除 `mocks/mockOption.ts` 与 URL 开关；`navigation.ts` / `workloadsRuntime.ts` / `workloadsRuntimeDetail.ts` 只保留数据与 builders；6 个 API 文件全部改为内联写法。
- 语义变化：DEV 下 mock 常开（无需 URL 参数）；生产构建仍由服务层 enhance 的 `import.meta.env.DEV` 守卫短路，行为不变。vitest 下相关 API 模块未被任何测试直接调用（machine 测试均 `vi.mock` 整体替换），不受影响。
- 账户列表 mock 因静态化不再响应 keyword 过滤（导航栏传空关键词，无影响）。
