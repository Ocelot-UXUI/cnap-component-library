## 修复：面包屑四维选择器 label 与下拉列表数据源统一（方向 A）

问题：account/application/environment 三维的下拉列表数据来自 `optionGroupMachine`（`optionGroups.*.data`），但外部 label 来自 `candidates`（`snapshot.accounts/applications/environments`），两条链路分离，导致选中账号后 label 不回显（candidates 归一化/加载失败会静默清空）。cluster 维已是单一来源（label + 下拉均取 `optionGroups.cluster.data`）。

方案：向 cluster 看齐，让其余三维的 label 也从各自已 mapped 的 option groups 派生，`candidates` 退化为纯粹的选中态校验/层级推断（不再喂显示）。

### 改动（单文件）

- `BreadcrumbContextSelectors.tsx`：
  - 新增纯函数 `findSelectedName(groups, id)`：在 `groups.all` 中按 `id === String(id)` 找到选中项的 `name`。
  - 三个 label 由 `selectedAccount?.name` / `selectedApplication?.name` / `selectedEnvironment?.environmentName`（取自 `snapshot.accounts/applications/environments`）改为 `findSelectedName(accountGroups|applicationGroups|environmentGroups, snapshot.*Id)`。
  - 删除基于 candidates 的 `selectedAccount/selectedApplication/selectedEnvironment` 三行。
  - 文件回收至 149 行（< 150 max-lines 约束）。

范围外（按用户决定本次不做）：`normalizeNavigationContext` 在 candidates 为空/失败时清空 accountId 导致「选中态不持久」的根因未修复，另开。

- 无该组件单测；行为为显示层派生调整，未新增测试。

## feat：Workloads 运行时 summary + 分组选择共享化（constate）

Plan：`docs/plans/2026-07-27-workload-shared-runtime-summary-plan.md`。

- `WorkloadsOverview/ResourceCard.tsx`：改消费共享 summary.resourceRequirements；parseResource 内联。删除 `useRuntimeSummary.ts`。
- `PodContentArea/index.tsx`：改消费共享 summary.podStatistics + operations；`groups` 按 groupId 前端过滤（接口不支持 groupId）；loading/error 用 groups 维度。删除 `usePodGroups.ts`。
